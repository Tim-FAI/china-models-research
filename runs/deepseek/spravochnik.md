Практический справочник по командам и флагам из твоего списка

Команды сгруппированы по разделам 2–8, как на фотографиях. Для каждой приведены назначение, указанные флаги, примеры и важные нюансы.

# Как пользоваться справочником

Примеры рассчитаны на Bash в Linux. Символ \$ в начале примера — приглашение терминала, вводить его не нужно. Пути и вывод могут отличаться в разных дистрибутивах и версиях программ.

- **Команда** — название программы или встроенной команды оболочки.

- **Аргумент** — объект, с которым работает команда: файл, каталог, пользователь, адрес сервера.

- **Флаг** — дополнительная настройка поведения команды.

- Абсолютный путь начинается с /; относительный отсчитывается от текущего каталога.

- **Код завершения 0 обычно означает успех; ненулевой код** — ошибка или ложный результат проверки.

> **Осторожно.** rm, chmod, chown, git reset --hard, git clean и rsync --delete могут привести к потере данных или изменению доступа. Перед запуском проверяй путь и направление копирования.

# 2. Навигация, файлы и базовые команды оболочки

## pwd

Показывает полный путь текущего каталога.

**Использование:** pwd

**ПРИМЕРЫ**

> pwd

**ПРИМЕР С ВЫВОДОМ**

> **\$ pwd**
>
> /home/anna/projects
>
> **→** Вывод: текущая папка — /home/anna/projects.
>
> **Нюанс** Полезно выполнить перед удалением, копированием или перемещением.

## cd

Меняет текущий каталог оболочки.

**Использование:** cd ПУТЬ

**ПРИМЕРЫ**

> cd .. — перейти на уровень выше
>
> cd - — вернуться в предыдущий каталог.

**ПРИМЕР С ВЫВОДОМ**

> **\$ pwd**
>
> /home/anna/projects/app
>
> **\$ cd ..**
>
> **\$ pwd**
>
> /home/anna/projects
>
> **\$ cd -**
>
> /home/anna/projects/app
>
> **→** cd .. поднял на уровень выше; cd - вернул в предыдущую папку и напечатал её путь.
>
> **Нюанс** cd без аргумента возвращает в домашний каталог. cd - переключает между двумя последними каталогами и печатает новый путь.

## ls

Показывает содержимое каталога.

**Использование:** ls \[флаги\] \[путь\]

- **-l** — Подробный («длинный») список: один файл — одна строка. В строке видно тип и права (например, -rw-r--r--), число ссылок, владельца, группу, размер в байтах, дату изменения и имя. Это самый частый флаг для ls: именно с ним смотрят, кому принадлежит файл и какие у него права. Пример: ls -l
- **-a** — Показать все файлы, включая скрытые. Скрытыми считаются имена, которые начинаются с точки (.bashrc, .git, .env). Дополнительно появляются две служебные записи: «.» — это текущий каталог, а «..» — родительский. Пример: ls -a
- **-h** — «Human-readable» — размеры печатаются в удобных единицах (K, M, G) вместо длинного числа байтов. Сам по себе флаг ничего не меняет: он работает только вместе с -l, поэтому почти всегда пишут -lh. Пример: ls -lh
- **-d** — Показать сам каталог, а не его содержимое. Обычный ls docs выведет файлы внутри docs, а ls -d docs выведет просто docs. Вместе с -l (ls -ld docs) покажет права и владельца самой папки — это нужно, когда проверяешь доступ к каталогу. Пример: ls -ld /var/log
- **-R** — Рекурсивный обход: сначала выводится содержимое каталога, затем содержимое каждого вложенного каталога, и так до самого низа. Каждая папка выводится под своим заголовком (путь с двоеточием). Для больших деревьев вывод получается очень длинным — его удобно отправить в less: ls -R \| less. Пример: ls -lR project/

**ПРИМЕРЫ**

> ls -lah
>
> ls -ld /var/log
>
> ls -lR project/

**ПРИМЕР С ВЫВОДОМ**

> **\$ ls -l**
>
> -rw-r--r-- 1 anna anna 6 Nov 10 10:00 file.txt
>
> drwxr-xr-x 2 anna anna 64 Nov 10 10:01 docs
>
> **\$ ls -a**
>
> . .. .git file.txt docs
>
> **\$ ls -lh**
>
> -rw-r--r-- 1 anna anna 6 Nov 10 10:00 file.txt
>
> **\$ ls -ld docs**
>
> drwxr-xr-x 2 anna anna 64 Nov 10 10:01 docs
>
> **→** -l показывает подробности, -a скрытые имена, -h удобные размеры, -d сам каталог, -R также его содержимое и вложенные папки.
>
> **Нюанс** -h особенно полезен вместе с -l. Скрытые файлы обычно начинаются с точки. -d не раскрывает содержимое каталога.

## mkdir

Создаёт каталог.

- **-p** — От слова parents («родители»). Создаёт всю цепочку вложенных каталогов за один раз: если нужных родительских папок ещё нет, они создаются автоматически. Кроме того, команда не ругается, если каталог уже существует, поэтому её безопасно запускать повторно, например в скриптах. Без -p команда mkdir a/b/c завершится ошибкой «No such file or directory», пока не существуют a и a/b. Пример: mkdir -p project/src/tests

**ПРИМЕРЫ**

> mkdir notes
>
> mkdir -p project/src/tests

**ПРИМЕР С ВЫВОДОМ**

> **\$ mkdir -p project/src/tests**
>
> **\$ find project -type d**
>
> project
>
> project/src
>
> project/src/tests
>
> **→** Одна команда создала всю цепочку каталогов, даже если project и src раньше не существовали.
>
> **Нюанс** Без -p родительская папка должна существовать заранее.

## cp

Копирует файлы и каталоги.

**Использование:** cp \[флаги\] ИСТОЧНИК НАЗНАЧЕНИЕ

- **-r** — Recursive — «рекурсивно». Копирует каталог целиком: сам каталог, все файлы внутри и все вложенные папки. Без -r команда cp откажется копировать каталог и напишет «-r not specified; omitting directory». Если каталога назначения ещё нет, он создаётся как копия исходного; если уже есть, исходный каталог окажется внутри него. Пример: cp -r photos/ backup/photos/

**ПРИМЕРЫ**

> cp a.txt b.txt
>
> cp -r photos/ backup/photos/

**ПРИМЕР С ВЫВОДОМ**

> **\$ cat file.txt**
>
> hello
>
> **\$ cp -r docs docs-backup**
>
> **\$ find docs-backup -type f**
>
> docs-backup/readme.txt
>
> docs-backup/guide.txt
>
> **→** cp file.txt copy.txt создаст копию файла; -r копирует каталог вместе с содержимым.
>
> **Нюанс** Копия не удаляет оригинал. Проверяй путь назначения, чтобы не затереть нужные данные.

## mv

Перемещает или переименовывает файл/каталог.

**Использование:** mv ИСТОЧНИК НАЗНАЧЕНИЕ

**ПРИМЕРЫ**

> mv draft.txt final.txt
>
> mv report.txt ~/Documents/

**ПРИМЕР С ВЫВОДОМ**

> **\$ mv draft.txt final.txt**
>
> **\$ ls**
>
> final.txt
>
> **→** Имя изменилось с draft.txt на final.txt; содержимое файла не переписывалось.
>
> **Нюанс** Если назначение — каталог, объект переместится внутрь него. При совпадении имён можно заменить существующий файл.

## rm

Удаляет файлы и каталоги. Обычно удаление не использует корзину.

- **-r** — Recursive — «рекурсивно». Удаляет каталог вместе со всем содержимым: файлами и вложенными папками. Без -r команда rm не удаляет каталоги и сообщает «is a directory». Помни: корзины нет, удалённое не вернуть. Пример: rm -r old_project
- **-f** — Force — «принудительно». Не задаёт вопросов перед удалением защищённых от записи файлов и не выдаёт ошибку, если файла не существует. Удобно в скриптах, но опасно в сочетании с -r: rm -rf удаляет всё без подтверждения. Пример: rm -f temp.txt
- **--** — Два дефиса означают «дальше флагов нет, всё остальное — имена файлов». Нужны, если имя файла начинается с дефиса: без них rm примет имя -old.txt за набор флагов и выдаст ошибку или сделает не то, что планировалось. Это универсальная защита и для других команд. Пример: rm -- -old.txt

**ПРИМЕРЫ**

> rm old.txt
>
> rm -r old-project/
>
> rm -rf -- ./cache

**ПРИМЕР С ВЫВОДОМ**

> **\$ rm -r old-project/**
>
> **\$ ls**
>
> *(каталога old-project больше нет)*
>
> **\$ rm -f missing.txt**
>
> *(ошибки из-за отсутствующего файла нет)*
>
> **\$ rm -- -draft**
>
> *(удалён файл с именем -draft)*
>
> **→** -r удаляет каталог с содержимым, -f не задаёт вопросов, -- прекращает разбор флагов.
>
> **Нюанс** Перед rm -rf проверь pwd и путь. -- позволяет указать имя, начинающееся с дефиса: rm -- -draft.

## cat

Выводит содержимое файлов подряд в терминал.

**ПРИМЕРЫ**

> cat notes.txt
>
> cat part1.txt part2.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ printf 'hello\n' \> file.txt**
>
> **\$ cat file.txt**

> hello
>

## echo

Печатает текст и аргументы.

- **-n** — Не добавлять перевод строки в конце вывода. Обычно echo после текста переходит на новую строку; с -n следующий вывод (или приглашение терминала) продолжится на той же строке. Полезно, когда нужно записать в файл строку без «хвостового» перевода. Пример: echo -n 'Привет, '
- **-e** — Включить обработку управляющих последовательностей внутри текста: — новая строка, табуляция, \\ — один обратный слеш. Без -e эти знаки печатаются буквально, как написаны. В разных оболочках поведение -e немного отличается — для строгого форматирования надёжнее printf. Пример: echo -e 'строка 1'

**ПРИМЕРЫ**

> echo -n "Имя: "
>
> echo -e "один\nдва"

**ПРИМЕР С ВЫВОДОМ**

> **\$ echo -n 'Name: '**
>
> Name: \$ echo -e 'one\ntwo'
>
> one
>
> two
>
> **→** -n не добавил перевод строки после Name:; -e превратил последовательность \n в переход на новую строку.
>
> **Нюанс** Поведение echo может отличаться в разных оболочках. Для точного форматирования лучше printf.

## chmod

Меняет права чтения, записи и выполнения.

- **+x** — Добавляет право выполнения (x — execute) всем трём категориям: владельцу, группе и остальным. Нужно, чтобы скрипт или программу можно было запустить как ./script.sh. Пример: chmod +x script.sh
- **u+x** — Читается так: «для u (user — владелец) добавить (+) право x (выполнение)». Остальные категории не меняются. Буквы категорий: u — владелец, g — группа, o — все остальные, a — все сразу. Знак + добавляет права, - убирает, = устанавливает ровно такие. Пример: chmod u+x script.sh
- **640** — Числовая запись прав — три цифры: для владельца, для группы, для остальных. Каждая цифра — сумма: чтение r = 4, запись w = 2, выполнение x = 1. Здесь 6 = 4+2 (читать и писать), 4 (только читать), 0 (ничего). Итог: владелец читает и пишет, группа только читает, остальные не имеют доступа — типично для личных файлов с чувствительными данными. Пример: chmod 640 secret.txt

**ПРИМЕРЫ**

> chmod +x script.sh
>
> chmod u+x script.sh
>
> chmod 640 secret.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ ls -l run.sh secret.txt**
>
> -rw-r--r-- 1 anna anna 20 run.sh
>
> -rw-r--r-- 1 anna anna 12 secret.txt
>
> **\$ chmod u+x run.sh**
>
> **\$ ls -l run.sh**
>
> -rwxr--r-- 1 anna anna 20 run.sh
>
> **\$ chmod 640 secret.txt**
>
> **\$ ls -l secret.txt**
>
> -rw-r----- 1 anna anna 12 secret.txt
>
> **→** u+x добавил владельцу право запуска; 640 означает владелец rw-, группа r--, остальные ---.
>
> **Нюанс** 640 = владелец rw-, группа r--, остальные без прав. Обычно менять права может владелец файла или root. Для каталога x означает возможность проходить внутрь.

## stat

Показывает метаданные файла: размер, права, владельца, даты.

- **-c** — Задаёт собственный формат вывода (от слова custom/format). Вместо длинной стандартной справки stat печатает только то, что описано шаблоном. В шаблоне знак % вводит код (см. ниже). Шаблон нужно брать в кавычки, чтобы оболочка не пыталась разобрать знаки % сама. Пример: stat -c '%n %s' file.txt
- **%n** — Код формата: имя файла.
- **%s** — Код формата: размер файла в байтах.
- **%A** — Код формата: права в привычном текстовом виде, например -rw-r--r--. (Код %a выводит те же права числом, например 644.)
- **%U** — Код формата: имя владельца файла. (Код %u выводит числовой номер владельца.)
- **%G** — Код формата: имя группы-владельца. (Код %g — числовой номер группы.)

**ПРИМЕРЫ**

> stat -c '%n %s %A %U:%G' report.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ stat -c '%n %s bytes %A %U:%G' file.txt**
>
> file.txt 6 bytes -rw-r--r-- anna:anna
>
> **→** %n — имя, %s — размер в байтах, %A — права, %U:%G — владелец и группа.
>
> **Нюанс** Кавычки вокруг формата нужны, чтобы оболочка не разбирала специальные символы.

## test

Проверяет условие; обычно ничего не печатает, а возвращает код 0 или 1.

- **-f** — Истина, если указанный путь существует и это обычный файл (не каталог, не устройство). Если файла нет или это каталог — ложь. Пример: test -f report.txt
- **-d** — Истина, если путь существует и это каталог. Часто используют перед копированием или входом в каталог, чтобы не получить ошибку. Пример: test -d logs
- **-s** — Истина, если файл существует и не пустой (размер больше нуля). Отличается от -f тем, что пустой файл даёт ложь. Полезно проверить, что программа действительно что-то записала. Пример: test -s data.csv

**ПРИМЕРЫ**

> test -f report.txt
>
> \[ -d logs \]
>
> \[ -s data.csv \]

**ПРИМЕР С ВЫВОДОМ**

> **\$ test -f file.txt; echo \$?**
>
> 0
>
> **\$ test -d file.txt; echo \$?**
>
> 1
>
> **\$ test -s empty.txt; echo \$?**
>
> 1
>
> **→** 0 означает, что условие истинно: file.txt — обычный файл. 1 означает, что проверка ложна.
>
> **Нюанс** Пробелы внутри \[ \] обязательны. Пример в Bash: if \[ -f file \]; then echo yes; fi.

> **→** Показаны три последние команды текущей истории оболочки.
>
> **Нюанс** Не вводи пароли и секретные токены прямо в команды: они могут сохраниться в истории.

## chown

Меняет владельца и/или группу файла.

**ПРИМЕРЫ**

> sudo chown alice report.txt
>
> sudo chown alice:developers project/

**ПРИМЕР С ВЫВОДОМ**

> **\$ ls -l report.txt**
>
> -rw-r--r-- 1 anna anna 80 report.txt
>
> **\$ sudo chown bob report.txt**
>
> **\$ ls -l report.txt**
>
> -rw-r--r-- 1 bob anna 80 report.txt
>
> **→** Владелец изменился на bob; группа осталась anna. Обычно менять владельца может root.
>
> **Нюанс** Обычно менять владельца может root. Не путай владельца и группу-владельца.

## chgrp

Меняет группу-владельца файла или каталога.

**ПРИМЕРЫ**

> chgrp developers report.txt
>
> chgrp -R developers shared/

**ПРИМЕР С ВЫВОДОМ**

> **\$ ls -l report.txt**
>
> -rw-r--r-- 1 anna anna 80 report.txt
>
> **\$ chgrp developers report.txt**
>
> **\$ ls -l report.txt**
>
> -rw-r--r-- 1 anna developers 80 report.txt
>
> **→** Группа стала developers. Обычный пользователь должен владеть объектом и состоять в целевой группе; иначе нужны права администратора.
>
> **Нюанс** Обычный пользователь должен быть владельцем объекта и состоять в целевой группе. Иначе нужны права администратора.

# 3. Просмотр и обработка текста

## head

Показывает начало файла; по умолчанию первые 10 строк.

- **-n N** — Показать первые N строк вместо десяти по умолчанию. Вместо N подставь число. Пробел между -n и числом необязателен: -n 5 и -n5 работают одинаково. Пример: head -n 5 app.log
- **-c N** — Показать первые N байтов, а не строк. Полезно для двоичных файлов или файлов без переводов строк. Помни: в UTF-8 русская буква занимает 2 байта, поэтому -c может «разрезать» букву пополам, и в конце появится нечитаемый символ. Пример: head -c 80 config.txt

**ПРИМЕРЫ**

> head -n 5 app.log
>
> head -c 80 config.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ cat file.txt**
>
> one
>
> two
>
> three
>
> four
>
> five
>
> **\$ head -n 2 file.txt**
>
> one
>
> two
>
> **\$ head -c 5 file.txt**
>
> one
>
> t
>
> **→** -n 2 вывел первые две строки; -c 5 вывел первые пять байтов.
>
> **Нюанс** -c считает байты, поэтому может разрезать многобайтовый символ UTF-8.

## tail

Показывает конец файла и может следить за добавлением новых строк.

- **-n N** — Показать последние N строк (по умолчанию 10). Чаще всего используют для просмотра свежих записей журнала. Пример: tail -n 20 app.log
- **-n +N** — Знак плюс меняет смысл: вывести всё, начиная со строки номер N, до самого конца. Например, -n +2 пропускает первую строку — удобно, чтобы убрать заголовок таблицы. Это не «последние N строк». Пример: tail -n +2 data.csv
- **-f** — Follow — «следить». Команда не завершается: после вывода последних строк она ждёт и печатает новые строки по мере того, как они дописываются в файл. Идеально для наблюдения за журналом в реальном времени. Остановить: Ctrl+C. Пример: tail -f /var/log/syslog

**ПРИМЕРЫ**

> tail -n 20 app.log
>
> tail -n +5 data.txt
>
> tail -f /var/log/syslog

**ПРИМЕР С ВЫВОДОМ**

> **\$ tail -n 2 file.txt**
>
> four
>
> five
>
> **\$ tail -n +3 file.txt**
>
> three
>
> four
>
> five
>
> **\$ tail -f app.log**
>
> *(показывает новые строки журнала по мере их появления; Ctrl+C остановит)*
>
> **→** -n N — последние N строк; -n +N — начиная со строки N до конца; -f следит за новыми данными.
>
> **Нюанс** Ctrl+C останавливает слежение. -n +5 — это всё с пятой строки до конца, а не последние пять строк.

## wc

Считает строки, слова, байты или символы.

- **-l** — Посчитать строки (точнее, знаки перевода строки). Самый частый вариант: сколько строк в файле или сколько результатов выдала другая команда в конвейере. Пример: wc -l access.log
- **-w** — Посчитать слова. Слово здесь — любая последовательность символов, отделённая пробелами, табуляциями или переводами строк. Пример: wc -w article.txt
- **-c** — Посчитать байты. Для английского текста байты совпадают с символами, а для русского — нет: каждая русская буква занимает 2 байта. Пример: wc -c file.bin
- **-m** — Посчитать символы (буквы, цифры, знаки). Для русского текста даёт меньшее число, чем -c, потому что считает буквы, а не байты. Если нужны именно «буквы», используй -m. Пример: wc -m article.txt

**ПРИМЕРЫ**

> wc -l access.log
>
> wc -w article.txt
>
> wc -c file.bin
>
> wc -m article.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ wc -l -w -c -m file.txt**
>
> 5 5 24 24 file.txt
>
> **→** В этом примере файл содержит 5 строк, 5 слов, 24 байта и 24 символа. Для кириллицы байтов обычно больше, чем символов.
>
> **Нюанс** Русская буква в UTF-8 часто занимает несколько байтов, поэтому -c и -m могут дать разные числа.

## less

Открывает файл для постраничного просмотра.

**Использование:** less ФАЙЛ

- **/текст** — Поиск вперёд. Нажми /, напиши слово и Enter — less перейдёт к первому совпадению и подсветит все найденные. Это команда внутри просмотрщика, а не путь к файлу. Пример: /error
- **n** — Перейти к следующему найденному совпадению (next). Нажимай несколько раз, чтобы пройтись по всем. Заглавная N — к предыдущему совпадению.
- **q** — Выйти из less и вернуться в терминал (quit). Если запутался в окне просмотра, нажми q.

**ПРИМЕРЫ**

> less /var/log/syslog

**ПРИМЕР С ВЫВОДОМ**

> **\$ less file.txt**
>
> *(откроется текст; внизу будет строка состояния)*
>
> /hello → найти hello
>
> n → перейти к следующему совпадению
>
> q → выйти
>
> **→** less не печатает весь файл сразу: он открывает его в прокручиваемом просмотрщике.
>
> **Нюанс** /error — команда поиска внутри less, а не путь к файлу.

## grep

Ищет строки по текстовому шаблону.

- **-n** — Перед каждой найденной строкой печатает её номер в файле и двоеточие. Помогает быстро перейти к нужному месту в редакторе. Пример: grep -n 'error' app.log
- **-i** — Не различать заглавные и строчные буквы: error, Error и ERROR считаются одним и тем же. Без -i поиск чувствителен к регистру. Пример: grep -i 'error' app.log
- **-v** — Инвертировать — вывести строки, в которых шаблон НЕ найден. Часто используется, чтобы выбросить комментарии или ненужный шум из вывода. Пример: grep -v '^#' config.ini
- **-c** — Не печатать сами строки, а вывести число строк, где найдено совпадение. Считаются строки, а не отдельные вхождения: если слово встречается дважды в одной строке, это всё равно одна строка. Пример: grep -c 'error' app.log
- **-w** — Искать слово целиком (word). Совпадение не должно быть частью более длинного слова: grep -w cat найдёт «cat», но не «concatenate» и не «cats». Пример: grep -w 'cat' words.txt
- **-o** — Печатать только совпавшую часть строки, а не строку целиком (only matching). Каждое совпадение выводится на отдельной строке. Удобно, чтобы вытащить из текста, например, все числа или адреса. Пример: grep -o '\[0-9\]\*' notes.txt
- **-E** — Extended — расширенные регулярные выражения. Включает удобные знаки: \| («или»), + («один или больше»), ? («ноль или один»), круглые скобки для групп. Без -E эти знаки приходится экранировать обратным слешем. Пример: grep -E 'error\|warning' app.log
- **-F** — Fixed — искать текст буквально, как написано. Точки, звёздочки, скобки и прочие специальные знаки теряют особый смысл. Нужно, когда ищешь строку вроде a.b*c и не хочешь, чтобы grep считал её шаблоном. Работает и быстрее. Пример: grep -F 'a.b*c' file.txt
- **-x** — Строка должна совпасть целиком, от начала до конца, а не содержать шаблон где-то внутри. Например, grep -x done найдёт только строки, состоящие ровно из слова done. Пример: grep -x 'done' status.txt
- **-f файл** — Взять шаблоны для поиска из файла: каждая строка файла — отдельный шаблон. Строка считается найденной, если подходит хотя бы под один из них. Удобно, когда искомых слов много. Пример: grep -f words.txt big.txt
- **-r** — Recursive — искать во всех файлах каталога и всех вложенных каталогов. Вместо имени файла указывается каталог (или точка для текущего). В выводе перед строкой добавляется имя файла, в котором она найдена. Пример: grep -rn 'TODO' src/
- **--include** — Работает вместе с -r: просматривать только те файлы, чьё имя подходит под маску. Маску берут в кавычки: '*.py' — все файлы с расширением .py. Так не придётся искать в картинках, архивах и прочем ненужном. Пример: grep -r --include='*.py' 'TODO' src/

**ПРИМЕРЫ**

> grep -ni "error" app.log
>
> grep -v "^#" config.ini
>
> grep -r --include="\*.py" "TODO" src/

**ПРИМЕР С ВЫВОДОМ**

> **\$ cat app.log**
>
> INFO started
>
> ERROR disk full
>
> error retry
>
> INFO stopped
>
> **\$ grep -ni 'error' app.log**
>
> 2:ERROR disk full
>
> 3:error retry
>
> **\$ grep -vc 'INFO' app.log**
>
> 2
>
> **\$ grep -ow 'disk' app.log**
>
> disk
>
> **→** -n добавил номера строк, -i игнорирует регистр, -v выбирает несовпавшие строки, -c считает строки с совпадением, -w ищет слово целиком, -o печатает только совпавшую часть.
>
> **Нюанс** -c считает строки, где есть совпадение, а не отдельные совпадения. -E понимает расширенные регулярные выражения; -F ищет буквальный текст.

## find

Обходит дерево каталогов и ищет файлы/папки по условиям.

- **-type f** — Отбирать только обычные файлы (file). Каталоги, ссылки и устройства в результат не попадут. Пример: find . -type f
- **-type d** — Отбирать только каталоги (directory). Помогает найти папку по имени или составить список подкаталогов. Пример: find . -type d -name cache
- **-name** — Отбирать объекты, имя которых подходит под шаблон. Знак \* заменяет любые символы, ? — один символ. Шаблон всегда берут в кавычки, чтобы оболочка не раскрыла его раньше времени. Различает регистр; для игнорирования регистра есть -iname. Пример: find . -name '\*.log'
- **-exec** — Выполнить команду для каждого найденного объекта. Вместо {} подставляется найденный путь. Команда заканчивается либо на ; (запустить отдельно для каждого объекта), либо на + (передать сразу пачкой — быстрее). Это мощный и опасный инструмент: сначала проверь список без -exec. Пример: find . -name '\*.tmp' -exec rm -- {} +
- **-print** — Напечатать найденный путь (каждый на отдельной строке). Это действие по умолчанию, если другое не указано, но его явно пишут, когда в выражении есть другие действия и нужно точно показать, что выводить. Пример: find . -type f -name '\*.log' -print
- **-print0** — Печатать найденные пути, разделяя их не переводом строки, а нулевым символом. Так имена с пробелами и даже с переводами строк не разваливаются на части. Почти всегда используется в паре с xargs -0. Пример: find . -type f -print0

**ПРИМЕРЫ**

> find . -type f -name '\*.log' -print
>
> find . -type d -name cache -print
>
> find . -type f -name '\*.tmp' -exec rm -- {} +

**ПРИМЕР С ВЫВОДОМ**

> **\$ find . -type f -name '\*.txt' -print**
>
> ./notes.txt
>
> ./docs/readme.txt
>
> **\$ find . -type d -name 'cache' -print**
>
> ./app/cache
>
> **\$ find . -type f -name '\*.tmp' -exec rm -- {} +**
>
> *(найденные .tmp-файлы удалены)*
>
> **→** find обходит дерево каталогов; -type f/d выбирает файлы/каталоги, -name задаёт маску имени, -exec запускает действие для найденного.
>
> **Нюанс** В -exec пара {} + передаёт найденные пути группами. Для имён с пробелами и переводами строк используй -print0 вместе с xargs -0. Перед удалением сначала выведи список.

## xargs

Преобразует входной поток в аргументы другой команды.

- **-0** — Считать, что элементы входного списка разделены нулевым символом, а не пробелами и переводами строк. Нужен в паре с find -print0: вместе они безопасно передают имена файлов с пробелами, кавычками и другими необычными символами. Без этого файл «my file.txt» превратится в два разных аргумента. Пример: find . -type f -print0 \| xargs -0 ls -l

**ПРИМЕРЫ**

> find . -type f -print0 \| xargs -0 file

**ПРИМЕР С ВЫВОДОМ**

> **\$ find . -type f -print0 \| xargs -0 printf '\<%s\>\n'**
>
> \<./file one.txt\>
>
> \<./notes.txt\>
>
> **→** -0 правильно передаёт имена с пробелами и другими специальными символами, если источник использует -print0.
>
> **Нюанс** -0 используй вместе с find -print0, чтобы имена файлов с пробелами не разбивались на части.

## cut

Вырезает поля из каждой строки.

- **-d** — Delimiter — разделитель. Указывает знак, которым разделены поля в строке: двоеточие, запятая, точка с запятой и т. п. По умолчанию разделитель — табуляция. Знак обычно берут в кавычки. Пример: cut -d ':' -f 1 /etc/passwd
- **-f** — Fields — номера полей, которые нужно оставить. Нумерация начинается с 1. Можно перечислять через запятую (-f 1,3), задавать диапазон (-f 2-4) или «до конца» (-f 2-). Без -d используется табуляция, а не пробел. Пример: cut -d ',' -f 2,4 data.csv

**ПРИМЕРЫ**

> cut -d ':' -f 1,3 /etc/passwd
>
> cut -d ',' -f 2,4 data.csv

**ПРИМЕР С ВЫВОДОМ**

> **\$ cat users.txt**
>
> anna:x:1001:1001
>
> bob:x:1002:1002
>
> **\$ cut -d ':' -f 1,3 users.txt**
>
> anna:1001
>
> bob:1002
>
> **→** -d ':' задаёт двоеточие-разделитель; -f 1,3 выбирает первое и третье поле.
>
> **Нюанс** Номера полей начинаются с 1. Простой cut не умеет полноценно разбирать CSV с запятыми внутри кавычек.

## sort

Сортирует строки.

- **-n** — Numeric — сортировать как числа. Без -n сортировка идёт по символам, и 10 окажется раньше 2, потому что «1» меньше «2». С -n числа упорядочиваются по значению: 2, 10, 30. Пример: sort -n numbers.txt
- **-r** — Reverse — обратный порядок: от большего к меньшему или от Я к А. Часто сочетают с -n (-rn), чтобы сверху оказались самые большие числа. Пример: sort -r names.txt
- **-u** — Unique — оставить только уникальные строки: повторяющиеся выбрасываются, остаётся по одной. Эквивалент sort \| uniq. Пример: sort -u names.txt
- **-t** — Задаёт знак-разделитель столбцов (field separator) для сортировки по полю. Пишут вместе с -k. Например, -t, значит, что столбцы разделены запятыми. Пример: sort -t, -k2 data.csv
- **-k** — Key — номер поля (столбца), по которому сортировать. -k2 — со второго поля и до конца строки, -k2,2 — строго только по второму полю. Для столбцов с числами добавь n: -k2,2n. Пример: sort -t, -k2,2 data.csv

**ПРИМЕРЫ**

> sort -n numbers.txt
>
> sort -r names.txt
>
> sort -u names.txt
>
> sort -t, -k2,2 data.csv

**ПРИМЕР С ВЫВОДОМ**

> **\$ cat numbers.txt**
>
> 10
>
> 2
>
> 30
>
> **\$ sort -n numbers.txt**
>
> 2
>
> 10
>
> 30
>
> **\$ sort -rn numbers.txt**
>
> 30
>
> 10
>
> 2
>
> **\$ sort -u names.txt**
>
> Anna
>
> Bob
>
> **→** -n сортирует как числа, -r меняет порядок, -u оставляет уникальные строки, -t и -k задают разделитель и поле сортировки.
>
> **Нюанс** Для CSV с кавычками sort не является полноценным CSV-парсером.

## uniq

Удаляет соседние повторы или подсчитывает их.

- **-c** — Count — перед каждой строкой печатает, сколько раз подряд она встретилась. Поскольку uniq сравнивает только соседние строки, перед ним почти всегда нужен sort, иначе повторы, стоящие далеко друг от друга, не склеятся. Пример: sort names.txt \| uniq -c

**ПРИМЕРЫ**

> sort names.txt \| uniq -c

**ПРИМЕР С ВЫВОДОМ**

> **\$ cat names.txt**
>
> Anna
>
> Anna
>
> Bob
>
> Bob
>
> Bob
>
> **\$ sort names.txt \| uniq -c**
>
> 2 Anna
>
> 3 Bob
>
> **→** uniq -c показывает, сколько раз подряд встретилась каждая строка; поэтому перед ним обычно ставят sort.
>
> **Нюанс** uniq сравнивает только соседние строки, поэтому перед подсчётом обычно нужен sort.

## diff

Сравнивает два файла.

- **-u** — Unified — компактный привычный формат: сначала два заголовка с именами файлов, затем блоки изменений. Строки со знаком «-» были в первом файле, но исчезли; со знаком «+» — появились во втором; строки без знака — неизменный контекст для ориентира. Именно такой вид у git diff. Пример: diff -u old.txt new.txt
- **-y** — Side by side — показать два файла рядом, в две колонки. Между колонками стоит знак: «\|» — строка изменена, «\<» — только в первом файле, «\>» — только во втором. Так наглядно сравнивать небольшие файлы. Пример: diff -y old.txt new.txt
- **--width** — Задаёт общую ширину вывода в символах. Используется вместе с -y, чтобы две колонки поместились в окно терминала и строки не обрезались. Пишется как --width=120 (знак равенства обязателен). Пример: diff -y --width=120 old.txt new.txt

**ПРИМЕРЫ**

> diff -u old.conf new.conf
>
> diff -y --width=120 old.txt new.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ diff -u old.txt new.txt**
>
> --- old.txt
>
> +++ new.txt
>
> @@ -1,2 +1,2 @@
>
> -hello
>
> +hello world
>
> same
>
> **→** -u показывает изменения в компактном формате: строки с минусом удалены, с плюсом добавлены. -y выводит файлы рядом.
>
> **Нюанс** Код 0 — различий нет; 1 — различия найдены; большее значение обычно означает ошибку.

## rg (ripgrep)

Быстро ищет текст по проекту.

- **-n** — Показывать номера строк (line number) рядом с найденным текстом. В терминале rg обычно делает это сам, но флаг пишут явно, чтобы вывод был одинаковым, например при записи в файл или передаче по конвейеру. Пример: rg -n 'TODO' .
- **--hidden** — Искать и в скрытых файлах и каталогах (имена с точкой в начале). По умолчанию rg их пропускает. Важно: правила из .gitignore при этом всё равно могут действовать, и часть файлов останется невидимой. Пример: rg --hidden 'token' ./project

**ПРИМЕРЫ**

> rg -n "TODO" .
>
> rg --hidden "token" ./project

**ПРИМЕР С ВЫВОДОМ**

> **\$ rg -n 'TODO' src**
>
> src/main.py:18:# TODO: validate input
>
> src/api.py:7:# TODO: add timeout
>
> **\$ rg --hidden 'settings' .**
>
> .config/app.ini:2:settings=dark
>
> **→** -n добавляет номера строк; --hidden включает поиск в скрытых файлах. Правила игнорирования проекта всё ещё могут действовать.
>
> **Нюанс** По умолчанию rg уважает .gitignore. --hidden включает скрытые файлы, но не обязательно отменяет правила игнорирования.

## column

Выравнивает текст в столбцы.

- **-t** — Table — превратить входной текст в таблицу: определить столбцы и выровнять их по ширине, так что значения встают ровно друг под другом. Столбцами считаются слова, разделённые пробелами или табуляциями, если не задан -s. Пример: printf 'name age' \| column -t
- **-s** — Separator — знак, который разделяет столбцы во входном тексте. Применяется вместе с -t. Например, для CSV с запятыми: -t -s ','. Без -s разделителями считаются пробелы. Пример: printf 'a,b,2' \| column -t -s ','

**ПРИМЕРЫ**

> printf 'name age\nAnna 21\nIvan 24\n' \| column -t
>
> printf 'a,b\n1,2\n' \| column -t -s,

**ПРИМЕР С ВЫВОДОМ**

> **\$ printf 'name age\nAnna 21\nIvan 24\n' \| column -t**
>
> name age
>
> Anna 21
>
> Ivan 24
>
> **\$ printf 'a,b\n1,2\n' \| column -t -s ','**
>
> a b
>
> 1 2
>
> **→** -t выравнивает столбцы; -s задаёт символ-разделитель.
>
> **Нюанс** Подходит для простых таблиц, но не заменяет полноценный парсер CSV.

## nano

Простой терминальный редактор.

- **Ctrl+O** — Сохранить файл (Write Out). Нужно нажать Ctrl и букву O (не ноль). Внизу появится вопрос об имени файла — нажми Enter, чтобы подтвердить. Знак ^ в подсказках внизу окна обозначает Ctrl.
- **Ctrl+X** — Выйти из nano. Если есть несохранённые изменения, спросит: сохранять ли. Y — да (затем Enter для подтверждения имени), N — нет, Ctrl+C — отмена и возврат в редактор.
- **Ctrl+W** — Поиск по тексту (Where is). Набери слово и нажми Enter — курсор перейдёт к первому совпадению. Повторный поиск вперёд — Alt+W.

**ПРИМЕРЫ**

> nano notes.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ nano notes.txt**
>
> *(откроется редактор)*
>
> Ctrl+O → сохранить; Enter → подтвердить имя файла
>
> Ctrl+W → найти текст
>
> Ctrl+X → выйти
>
> **→** В nano сочетания выполняются с Ctrl; внизу окна показаны подсказки.
>
> **Нюанс** Ctrl+O — Ctrl и буква O, не цифра 0.

## vim

Редактор с режимами.

- **i** — Перейти в режим вставки (Insert). После этого клавиши печатают текст, как в обычном редакторе. В нижней строке появится слово INSERT.
- **Esc** — Вернуться из режима вставки в обычный режим. В обычном режиме клавиши не печатают текст, а выполняют команды. Если запутался, нажми Esc один-два раза.
- **:w** — Сохранить файл (write). Все команды с двоеточием вводятся в обычном режиме: нажимаешь :, пишешь команду и подтверждаешь Enter.
- **:q** — Выйти из Vim (quit). Сработает, только если нет несохранённых изменений; иначе Vim напишет об этом и не выйдет.
- **:q!** — Выйти без сохранения: все несохранённые изменения будут потеряны. Восклицательный знак значит «принудительно». Спасает, если случайно что-то испортил.
- **:wq** — Сохранить и выйти одной командой (write + quit). Самый частый способ завершить работу после правок.
- **dd** — Удалить текущую строку целиком (она также помещается во внутренний буфер). Работает в обычном режиме. Чтобы удалить несколько строк, поставь число перед командой: 3dd.
- **u** — Отменить последнее изменение (undo). Нажимай несколько раз, чтобы отменить несколько действий подряд. Вернуть отменённое — Ctrl+R.

**ПРИМЕРЫ**

> vim notes.txt

**ПРИМЕР С ВЫВОДОМ**

> **\$ vim notes.txt**
>
> *(откроется редактор)*
>
> i → начать ввод текста
>
> Esc → вернуться в командный режим
>
> :w → сохранить
>
> :q → выйти
>
> :wq → сохранить и выйти
>
> :q! → выйти без сохранения
>
> dd → удалить строку
>
> u → отменить действие
>
> **→** Vim имеет режим ввода и командный режим; перед командами с двоеточием нажми Esc.
>
> **Нюанс** Команды с двоеточием вводятся после Esc и подтверждаются Enter. :q! отбрасывает несохранённые изменения.

## printf

Выводит данные по формату.

- **%s** — Метка-заполнитель для строки (string). Вместо неё подставляется очередной аргумент из списка после формата. Если аргументов больше, чем меток, формат применяется повторно — на этом основан приём printf '%s' a b c, который печатает каждый элемент в своей строке. Пример: printf '%s %s' Linux Bash
- \*\*\* — Перевод строки (new line). В отличие от echo, printf сам перевод строки в конце не добавляет, поэтому нужно писать в формате явно. Ещё бывает табуляция. Пример: printf '%s' 'hello'

**ПРИМЕРЫ**

> printf '%s\n' 'hello'
>
> printf '%s %s\n' Linux Bash

**ПРИМЕР С ВЫВОДОМ**

> **\$ printf '%s\n' 'hello'**
>
> hello
>
> **\$ printf '%s %s\n' Linux Bash**
>
> Linux Bash
>
> **→** %s подставляет текст, \n переводит курсор на новую строку. В отличие от echo, printf не добавляет перевод строки сам.
>
> **Нюанс** printf не добавляет перевод строки автоматически, в отличие от привычного поведения echo.

# 4. Git в терминале

## git init

Создаёт репозиторий Git.

- **--bare** — Создаёт «голый» репозиторий: в нём нет рабочей папки с файлами проекта, а лежат только служебные данные Git (история, ветки). Такие репозитории используют как общее хранилище на сервере, куда все отправляют изменения через git push. В «голый» репозиторий нельзя непосредственно редактировать файлы и делать коммиты. Принято давать им имена с окончанием .git. Пример: git init --bare project.git
- **-q** — Quiet — тихий режим: не печатать сообщение «Initialized empty Git repository…». Полезно в скриптах, где не нужен лишний вывод. Ошибки при этом по-прежнему выводятся. Пример: git init -q

**ПРИМЕРЫ**

> git init
>
> git init --bare project.git
>
> git init -q

**ПРИМЕР С ВЫВОДОМ**

> **\$ git init**
>
> Initialized empty Git repository in /home/anna/project/.git/
>
> **\$ git init --bare shared.git**
>
> Initialized empty Git repository in /home/anna/shared.git/
>
> **→** Обычный репозиторий содержит рабочие файлы и папку .git; bare-репозиторий хранит только данные Git и часто используется как серверный.
>
> **Нюанс** Обычный git init создаёт .git внутри проекта. Bare-репозитории часто используют на сервере.

## git status

Показывает изменённые, подготовленные и неотслеживаемые файлы.

- **--short** — Краткий формат: каждый изменённый файл — одна короткая строка с двумя символами состояния слева. Первый символ — состояние в индексе (подготовлено к коммиту), второй — в рабочей папке. Основные значки: M — изменён, A — добавлен, D — удалён, ?? — новый, ещё не отслеживаемый. Занимает гораздо меньше места, чем обычный вывод. Есть сокращение -s. Пример: git status --short
- **--ignored** — Дополнительно показывает файлы, которые Git игнорирует по правилам из .gitignore (они помечаются значком !!). Обычно такие файлы скрыты. Флаг помогает выяснить, куда «пропал» файл или какие сборочные папки лежат в проекте. Пример: git status --ignored

**ПРИМЕРЫ**

> git status --short
>
> git status --ignored

**ПРИМЕР С ВЫВОДОМ**

> **\$ git status --short**
>
> M app.py
>
> ?? notes.txt
>
> !! build/
>
> **→** M — изменён отслеживаемый файл; ?? — новый неотслеживаемый; !! — игнорируемый файл (при --ignored).
>
> **Нюанс** В коротком выводе два символа описывают состояние индекса и рабочей папки.

## git add

Добавляет изменения в индекс для будущего коммита.

- **-f** — Force — принудительно добавить в индекс файл, который перечислен в .gitignore и поэтому обычно не добавляется. Без -f Git ответит, что файл игнорируется. Применяй осознанно: часто такие файлы игнорируют не случайно (пароли, сборки, временные данные). Пример: git add -f build/output.zip

**ПРИМЕРЫ**

> git add README.md
>
> git add .
>
> git add -f build/output.zip

**ПРИМЕР С ВЫВОДОМ**

> **\$ git add app.py**
>
> **\$ git status --short**
>
> M app.py
>
> **\$ git add -f build/output.zip**
>
> **→** После add изменение попало в индекс (подготовлено к коммиту). -f принудительно добавляет файл, даже если он игнорируется.
>
> **Нюанс** add ещё не создаёт коммит. Не добавляй пароли, токены и приватные ключи.

## git commit

Записывает подготовленные изменения в историю.

- **-m** — Message — задать сообщение коммита прямо в командной строке, без открытия редактора. Сообщение берут в кавычки. Хорошее сообщение коротко объясняет, что и зачем изменено. Пример: git commit -m 'Add login page'
- **-a** — All — перед коммитом автоматически подготовить все изменённые и удалённые файлы, которые Git уже отслеживает; команду git add для них вводить не надо. Важно: новые файлы, которых Git ещё не знает, этот флаг не добавляет — их по-прежнему нужно добавить через git add. Пример: git commit -a -m 'Fix tracked files'
- **--amend** — Заменить последний коммит новым: можно поправить его сообщение или добавить забытые файлы (сначала git add, затем --amend). Старый коммит исчезает из истории, а вместо него появляется новый с другим идентификатором. Не делай этого с коммитами, которые уже отправлены другим людям: у них история разойдётся. Пример: git commit --amend -m 'Correct message'

**ПРИМЕРЫ**

> git commit -m "Add page"
>
> git commit -a -m "Fix tracked files"
>
> git commit --amend -m "Correct message"

**ПРИМЕР С ВЫВОДОМ**

> **\$ git commit -m 'Add login page'**
>
> \[main 4ac91d2\] Add login page
>
> 2 files changed, 18 insertions(+)
>
> **→** -m задаёт сообщение; -a включает изменения уже отслеживаемых файлов; --amend заменяет последний коммит, а не создаёт обычный новый.
>
> **Нюанс** -a не добавляет новые неотслеживаемые файлы. --amend переписывает последний коммит; после публикации это может создать проблемы другим участникам.

## git log

Показывает историю коммитов.

- **--oneline** — Короткий формат: один коммит — одна строка, в ней сокращённый идентификатор (хэш) и заголовок сообщения. Удобно просматривать большую историю одним взглядом. Пример: git log --oneline
- **-N** — Число вместо N ограничивает вывод последними N коммитами: -3 покажет три последних. Без этого флага выводится вся история, и придётся листать. Хорошо сочетается с --oneline. Пример: git log --oneline -5

**ПРИМЕРЫ**

> git log --oneline
>
> git log -5

**ПРИМЕР С ВЫВОДОМ**

> **\$ git log --oneline -3**
>
> 4ac91d2 Add login page
>
> 18b7a10 Fix header
>
> c02d114 Initial commit
>
> **→** --oneline показывает короткий ID и сообщение; -3 ограничивает вывод тремя последними коммитами.
>
> **Нюанс** Для выхода из постраничного просмотра нажми q.

## git diff

Показывает различия между рабочими файлами, индексом и коммитом.

- **--cached** — Показывает различия для подготовленных изменений: то, что уже добавлено в индекс через git add, по сравнению с последним коммитом. Обычный git diff без флага, наоборот, показывает ещё не подготовленные изменения. Синоним: --staged. Удобно проверить, что именно попадёт в коммит. Пример: git diff --cached

**ПРИМЕРЫ**

> git diff
>
> git diff --cached

**ПРИМЕР С ВЫВОДОМ**

> **\$ git diff --cached**
>
> +print('hello')
>
> **→** Показывает подготовленные изменения: то, что уже добавлено в индекс, но ещё не записано коммитом.
>
> **Нюанс** Обычный diff сравнивает рабочую папку с индексом; --cached — индекс с последним коммитом.

## git restore

Восстанавливает файлы или снимает их с подготовки.

- **--staged** — Снимает файл с подготовки: убирает его из индекса, как будто git add не выполнялся. Сами изменения в файле остаются в рабочей папке — ничего не теряется. Без этого флага git restore наоборот отбрасывает изменения в рабочем файле и возвращает его к прежнему состоянию, что необратимо. Пример: git restore --staged app.py

**ПРИМЕРЫ**

> git restore --staged app.py

**ПРИМЕР С ВЫВОДОМ**

> **\$ git restore --staged app.py**
>
> **\$ git status --short**
>
> M app.py
>
> **→** Файл убран из индекса, но изменения в самом app.py остались. Это не удаляет твою работу.
>
> **Нюанс** Полезно, если случайно выполнил(а) git add. Изменения останутся на диске.

## git revert

Создаёт новый коммит, отменяющий изменения выбранного коммита.

- **--no-edit** — Не открывать редактор для сообщения коммита: используется стандартное сообщение вида «Revert '…'». Удобно, когда не нужно писать пояснение или в скриптах. Сам revert не удаляет старый коммит, а создаёт новый, который отменяет его изменения, поэтому история остаётся нетронутой. Пример: git revert --no-edit 4ac91d2

**ПРИМЕРЫ**

> git revert --no-edit a1b2c3d

**ПРИМЕР С ВЫВОДОМ**

> **\$ git revert --no-edit 4ac91d2**
>
> \[main 91ab220\] Revert 'Add login page'
>
> 2 files changed, 18 deletions(-)
>
> **→** Создан новый коммит, который отменяет изменения указанного коммита; старая история не стирается.
>
> **Нюанс** В отличие от reset, revert сохраняет историю и добавляет обратный коммит. При конфликтах их нужно разрешить.

## git switch

Переключает ветку.

- **-c** — Create — создать новую ветку с указанным именем и сразу переключиться на неё. Новая ветка начинается с текущего коммита. Без -c git switch умеет только переходить на уже существующие ветки. Пример: git switch -c feature/search

**ПРИМЕРЫ**

> git switch main
>
> git switch -c feature/search

**ПРИМЕР С ВЫВОДОМ**

> **\$ git switch -c feature/search**
>
> Switched to a new branch 'feature/search'
>
> **\$ git branch --show-current**
>
> feature/search
>
> **→** -c создал новую ветку и сразу переключил на неё.
>
> **Нюанс** Незакоммиченные изменения могут помешать переключению, если будут перезаписаны.

## git merge

Вливает историю другой ветки в текущую.

**Использование:** git merge ВЕТКА

**ПРИМЕРЫ**

> git merge feature/search
>
> git merge --abort

**ПРИМЕР С ВЫВОДОМ**

> **\$ git switch main**
>
> Switched to branch 'main'
>
> **\$ git merge feature/search**
>
> Updating 18b7a10..4ac91d2
>
> Fast-forward
>
> app.py \| 4 ++++
>
> 1 file changed, 4 insertions(+)
>
> **→** Ветка feature/search влита в main. «Fast-forward» значит, что в main не было своих новых коммитов, и Git просто передвинул указатель вперёд.
>
> **Нюанс** Влить можно только в ту ветку, на которой ты сейчас находишься: сначала git switch в нужную. Если Git не может объединить изменения сам, он остановится с сообщением о конфликте: открой помеченные файлы, исправь их, затем git add и git commit. Отменить слияние в процессе можно командой git merge --abort.

## git branch

Показывает и управляет ветками.

- **--show-current** — Напечатать только имя текущей ветки, без списка всех остальных. Удобно для скриптов и быстрой проверки, где ты находишься. Если находишься не на ветке (в состоянии detached HEAD), ничего не выведет. Пример: git branch --show-current
- **-d** — Delete — удалить ветку, но только безопасно: Git откажется, если в ветке есть коммиты, которые ещё не влиты в другую ветку. Так работа не потеряется случайно. Удалить принудительно можно через -D (заглавная). Нельзя удалить ветку, на которой ты сейчас находишься. Пример: git branch -d old-feature
- **-vv** — Дважды verbose — очень подробный список веток: для каждой показывает хэш последнего коммита, его сообщение и связанную удалённую ветку (upstream) в квадратных скобках, а также отставание или опережение («ahead», «behind»). Пример: git branch -vv

**ПРИМЕРЫ**

> git branch --show-current
>
> git branch -d old-feature
>
> git branch -vv

**ПРИМЕР С ВЫВОДОМ**

> **\$ git branch --show-current**
>
> feature/search
>
> **\$ git branch -vv**
>
> \* feature/search 4ac91d2 \[origin/feature/search\] Add search
>
> main 18b7a10 \[origin/main\] Fix header
>
> **→** --show-current печатает текущую ветку; -vv показывает последние коммиты и связь с удалёнными ветками; -d удаляет слитую ветку.
>
> **Нюанс** -d не удалит ветку, если Git считает, что изменения ещё не слиты.

## git clone

Создаёт локальную копию удалённого репозитория.

- **--depth** — Создаёт «мелкий» клон: скачивается только указанное число последних коммитов, а не вся история. Например, --depth 1 берёт лишь самое свежее состояние. Скачивание получается быстрее и места занимает меньше, но старых коммитов локально не будет, и часть команд (поиск по истории, некоторые слияния) работает ограниченно. Пример: git clone --depth 1 https://example.org/team/app.git

**ПРИМЕРЫ**

> git clone https://example.org/team/app.git
>
> git clone --depth 1 https://example.org/team/app.git

**ПРИМЕР С ВЫВОДОМ**

> **\$ git clone --depth 1 https://example.org/team/app.git**
>
> Cloning into 'app'...
>
> remote: Enumerating objects: 12, done.
>
> Receiving objects: 100% (12/12), done.
>
> **→** --depth 1 скачал только самый свежий слой истории, поэтому загрузка меньше, но старых коммитов локально нет.
>
> **Нюанс** --depth 1 быстрее для большой истории, но не скачивает все старые коммиты.

## git remote

Показывает адреса удалённых репозиториев.

- **-v** — Verbose — подробный вывод. Вместо простого списка имён (например, origin) показывает для каждого удалённого репозитория адрес URL и пометку, для чего он используется: (fetch) — откуда получать изменения, (push) — куда отправлять. Обычно адреса совпадают, но могут и отличаться. Пример: git remote -v

**ПРИМЕРЫ**

> git remote -v

**ПРИМЕР С ВЫВОДОМ**

> **\$ git remote -v**
>
> origin https://example.org/team/app.git (fetch)
>
> origin https://example.org/team/app.git (push)
>
> **→** -v показывает адреса, откуда Git получает изменения и куда отправляет.
>
> **Нюанс** Стандартное имя удалённого репозитория часто origin.

## git fetch

Загружает новые объекты и обновляет ссылки на удалённые ветки, не меняя твои рабочие файлы.

**Использование:** git fetch \[УДАЛЁННЫЙ\]

**ПРИМЕРЫ**

> git fetch
>
> git fetch origin

**ПРИМЕР С ВЫВОДОМ**

> **\$ git fetch**
>
> From https://example.org/team/app
>
> 18b7a10..91ab220 main -\> origin/main
>
> **→** Git скачал новые коммиты и обновил origin/main. Твоя ветка main и рабочие файлы остались прежними, поэтому команда безопасна.
>
> **Нюанс** Fetch только забирает данные. Чтобы влить их в текущую ветку, выполни git merge origin/main. Команда git pull — это fetch и merge одним действием.

## git pull

Получает изменения с удалённого репозитория и интегрирует их в текущую ветку (fetch и merge в одном действии).

**Использование:** git pull \[УДАЛЁННЫЙ\] \[ВЕТКА\]

**ПРИМЕРЫ**

> git pull
>
> git pull origin main

**ПРИМЕР С ВЫВОДОМ**

> **\$ git pull**
>
> Updating 18b7a10..91ab220
>
> Fast-forward
>
> README.md \| 2 +-
>
> 1 file changed, 1 insertion(+), 1 deletion(-)
>
> **→** Новые коммиты загружены с сервера и сразу применены к текущей ветке.
>
> **Нюанс** Перед pull лучше закоммитить свою работу или убрать её в тайник (git stash): иначе возможны конфликты. Если конфликт всё же возник, действуй как при git merge. Хочешь сначала посмотреть, что изменилось на сервере, — сделай git fetch.

## git push

Отправляет локальные коммиты на удалённый сервер.

- **-u** — Set upstream — отправить ветку и запомнить связь между локальной веткой и удалённой. После этого в дальнейшем достаточно писать просто git push или git pull без указания имени удалённого репозитория и ветки. Нужен обычно один раз — при первой отправке новой ветки. Пример: git push -u origin main

**ПРИМЕРЫ**

> git push -u origin main

**ПРИМЕР С ВЫВОДОМ**

> **\$ git push -u origin main**
>
> Enumerating objects: 5, done.
>
> Writing objects: 100% (3/3), 420 bytes \| 420.00 KiB/s, done.
>
> branch 'main' set up to track 'origin/main'.
>
> **→** -u запоминает удалённую ветку как upstream; следующие отправки обычно можно делать командой git push.
>
> **Нюанс** После настройки upstream часто достаточно git push без указания ветки.

## git clean

Удаляет неотслеживаемые файлы и каталоги.

- **-n** — Dry run — «пробный запуск»: только показать, что было бы удалено, но ничего не удалять. Всегда начинай с него: команда git clean необратима, удалённые неотслеживаемые файлы нигде не сохраняются. Пример: git clean -n
- **-d** — Включить в работу не только файлы, но и неотслеживаемые каталоги. Без -d каталоги, не известные Git, остаются нетронутыми. Пример: git clean -nd
- **-f** — Force — «разрешаю». Git по умолчанию отказывается удалять файлы, пока в настройках не отключена защита или не указан этот флаг. Именно с -f удаление реально происходит. Без -f (и без -n) команда выдаст ошибку. Пример: git clean -fd
- **-x** — Включить в удаление и файлы, которые игнорируются по .gitignore (обычно git clean их не трогает). Так можно полностью очистить проект до чистого состояния, но вместе с этим удалятся сборки, локальные настройки, кэш, файлы окружения. Очень опасная комбинация: -fdx. Пример: git clean -nx

**ПРИМЕРЫ**

> git clean -n
>
> git clean -nd
>
> git clean -fdx

**ПРИМЕР С ВЫВОДОМ**

> **\$ git clean -n**
>
> Would remove draft.tmp
>
> **\$ git clean -nd**
>
> Would remove cache/
>
> **\$ git clean -fd**
>
> Removing draft.tmp
>
> Removing cache/
>
> **→** -n только показывает, что будет удалено; -d включает каталоги; -f разрешает удаление; -x также включает игнорируемые файлы. Безопасно сначала запускать -n.
>
> **Нюанс** Сначала всегда запускай -n. -fdx может удалить сборки, локальные настройки и файлы, скрытые через .gitignore.

## git config

Читает и меняет настройки Git.

- **--global** — Работать с настройками текущего пользователя (хранятся в файле ~/.gitconfig) — они действуют во всех репозиториях. Без флага (или с --local) настройка сохраняется только в текущем репозитории. Так задают имя и почту автора коммитов один раз для всех проектов. Пример: git config --global user.name 'Anna'
- **--unset** — Удалить настройку целиком (а не заменить значение). Указывают вместе с областью и именем параметра. После удаления Git вернётся к значению по умолчанию или к настройке более «высокого» уровня. Пример: git config --global --unset user.email

**ПРИМЕРЫ**

> git config --global user.name "Anna"
>
> git config --global user.email "anna@example.com"
>
> git config --global --unset user.email

**ПРИМЕР С ВЫВОДОМ**

> **\$ git config --global user.name 'Anna'**
>
> **\$ git config --global user.name**
>
> Anna
>
> **\$ git config --global --unset user.email**
>
> *(значение user.email удалено из глобальных настроек)*
>
> **→** --global меняет настройки пользователя; --unset удаляет выбранный параметр.
>
> **Нюанс** Локальные настройки репозитория могут перекрывать глобальные.

## git reset

Перемещает указатель ветки и меняет индекс/рабочие файлы.

- **--hard** — Жёсткий сброс: и указатель ветки, и индекс, и рабочие файлы приводятся к состоянию указанного коммита. Все незакоммиченные изменения в отслеживаемых файлах безвозвратно теряются. Часто используют так: git reset --hard HEAD — отбросить все текущие правки и вернуться к последнему коммиту. Сначала сохрани нужное через git stash или коммит. Пример: git reset --hard HEAD

**ПРИМЕРЫ**

> git reset --hard HEAD

**ПРИМЕР С ВЫВОДОМ**

> **\$ git reset --hard HEAD**
>
> HEAD is now at 4ac91d2 Add login page
>
> **→** Индекс и отслеживаемые файлы приведены к последнему коммиту. Незакоммиченные изменения будут потеряны без простого способа вернуть их.
>
> **Нюанс** В исходном сообщении была опечатка get reset — правильно git reset. --hard уничтожает незакоммиченные изменения в отслеживаемых файлах.

## git reflog

Показывает локальную историю перемещений ссылок (HEAD и веток): переключения, коммиты, сбросы.

**Использование:** git reflog

**ПРИМЕРЫ**

> git reflog

**ПРИМЕР С ВЫВОДОМ**

> **\$ git reflog**
>
> 91ab220 HEAD@{0}: revert: Revert "Add login page"
>
> 4ac91d2 HEAD@{1}: commit: Add login page
>
> 18b7a10 HEAD@{2}: commit: Fix header
>
> **→** Список действий в обратном порядке: HEAD@{0} — самое последнее. Слева — идентификаторы коммитов, к которым вело каждое действие.
>
> **Нюанс** Reflog хранится только на твоём компьютере и не отправляется на сервер. Он помогает найти «потерянные» коммиты, например после git reset --hard: найди нужный идентификатор и вернись к нему. Записи хранятся ограниченное время (по умолчанию порядка 90 дней).

## git stash

Временно прячет незакоммиченные изменения.

- **-u** — Include untracked — убрать в тайник и неотслеживаемые файлы (новые файлы, которые ещё не добавлены через git add). Без -u они остаются в рабочей папке. Игнорируемые файлы всё равно не затрагиваются. Пример: git stash -u
- **list** — Показать список всех сохранённых тайников. Каждая запись выглядит как stash@{0}: описание, где 0 — самый свежий. Нужен, когда сохранений несколько и надо понять, какое применять. Пример: git stash list
- **pop** — Применить последний тайник (stash@{0}) к рабочей папке и удалить его из списка. Если при применении возникли конфликты, тайник не удаляется — чтобы сохранённое не пропало. Если нужно применить, но оставить копию, используй git stash apply. Пример: git stash pop

**ПРИМЕРЫ**

> git stash -u
>
> git stash list
>
> git stash pop

**ПРИМЕР С ВЫВОДОМ**

> **\$ git stash -u**
>
> Saved working directory and index state WIP on main: 4ac91d2 Add login page
>
> **\$ git stash list**
>
> stash@{0}: WIP on main: 4ac91d2 Add login page
>
> **\$ git stash pop**
>
> On branch main
>
> Changes not staged for commit:
>
> modified: app.py
>
> **→** -u включает новые неотслеживаемые файлы; list показывает сохранения; pop возвращает последнее и удаляет его из списка при успехе.
>
> **Нюанс** Если при pop возник конфликт, разреши его вручную. Stash — временное хранилище, не постоянный коммит.

## git rm

Удаляет файл из индекса Git.

- **--cached** — Удалить файл только из индекса Git (перестать его отслеживать), а сам файл на диске оставить. Нужно, когда файл случайно попал в репозиторий (например, с паролями) и теперь его надо исключить, но сохранить локально. После этого полезно добавить файл в .gitignore. Без --cached git rm удаляет и из индекса, и с диска. Пример: git rm --cached secret.env

**ПРИМЕРЫ**

> git rm --cached .env

**ПРИМЕР С ВЫВОДОМ**

> **\$ git rm --cached .env**
>
> rm '.env'
>
> **\$ git status --short**
>
> D .env
>
> ?? .env
>
> **→** Файл убран из индекса Git, но остаётся на диске. Добавь .env в .gitignore, чтобы случайно не добавить его снова.
>
> **Нюанс** Если секрет уже отправлялся в удалённый репозиторий, его нужно заменить/отозвать.

## git check-ignore

Показывает, какое правило игнорирования скрывает файл.

- **-v** — Verbose — не просто сообщить, игнорируется ли файл, а показать, какое именно правило это решило: из какого файла, на какой строке и каким шаблоном. Очень помогает, когда непонятно, почему Git «не видит» файл. Пример: git check-ignore -v build/app.log

**ПРИМЕРЫ**

> git check-ignore -v .env

**ПРИМЕР С ВЫВОДОМ**

> **\$ git check-ignore -v .env**
>
> .gitignore:3:.env .env
>
> **→** Показано, что файл игнорируется правилом .env в третьей строке .gitignore.
>
> **Нюанс** Помогает понять, почему файл не появляется как обычный untracked в git status.

## bash

Запускает Bash или выполняет строку команд.

- **-c** — Command — выполнить команды, переданные в виде текста (строки) после флага, и завершиться. Строку берут в кавычки. Полезно запускать несколько команд как одну (например, через &&), передавать команду в ssh, cron или другую программу, а также проверять, как команда поведёт себя в «чистой» оболочке. >

>

>
> **Нюанс** Кавычки важны: внешняя оболочка может обработать \$переменные и специальные символы ещё до запуска Bash.

## python3

Запускает Python, модуль или код из строки.

- **-m** — Module — запустить модуль Python как программу, найдя его по имени в установленных библиотеках. Так запускают встроенные и сторонние инструменты: python3 -m venv (создать окружение), python3 -m pip (pip именно для этого Python), python3 -m http.server (простой веб-сервер). Пример: python3 -m venv .venv
- **-c** — Command — выполнить код Python, написанный прямо в командной строке, без создания файла. Код берут в кавычки. Подходит для быстрых проверок и вычислений. Пример: python3 -c 'print(2 + 2)'
- **--version** — Напечатать версию Python и завершиться, ничего не запуская. Помогает убедиться, какая именно версия используется в системе. Пример: python3 --version

**ПРИМЕРЫ**

>
> python3 -m http.server 8000
>
> python3 -c "print(2+2)"

**ПРИМЕР С ВЫВОДОМ**

> **\$ python3 --version**
>
> Python 3.12.2
>
> **\$ python3 -c 'print(2 + 2)'**
>
> 4
>
> **\$ python3 -m http.server 8000**
>
> Serving HTTP on 0.0.0.0 port 8000 ...
>
> **→** --version показывает версию; -c выполняет переданный код; -m запускает модуль.
>
> **Нюанс** Запускай нужный Python из виртуального окружения проекта.

## pip

Устанавливает Python-пакеты.

- **install -r** — Установить все пакеты, перечисленные в файле зависимостей (обычно requirements.txt): по одному пакету на строку, иногда с версиями. Так воспроизводят окружение проекта одной командой. Лучше выполнять внутри виртуального окружения, чтобы не засорять системный Python. Пример: pip install -r requirements.txt
- **install -q** — Quiet — тихая установка: подробный вывод (скачивание, сборка) скрывается, остаются только предупреждения и ошибки. Удобно в скриптах и в журналах сборки. Пример: pip install -q requests
- **--version** — Показать версию pip и путь к каталогу, где он работает, и версию Python, к которой он относится. Полезно, если pip и Python разных версий и пакеты ставятся «не туда». Пример: pip --version

**ПРИМЕРЫ**

> python3 -m pip install -r requirements.txt
>
> python3 -m pip install -q requests
>
> python3 -m pip --version

**ПРИМЕР С ВЫВОДОМ**

> **\$ python3 -m pip --version**
>
> pip 24.0 from /home/anna/project/.venv/lib/python3.12/site-packages/pip (python 3.12)
>
> **\$ python3 -m pip install -q requests**
>
> *(пакет установлен; при успехе тихий режим почти ничего не печатает)*
>
> **→** -r читает список пакетов из requirements.txt; -q уменьшает сообщения; --version показывает версию pip.
>
> **Нюанс** Запуск через python3 -m pip помогает не перепутать pip от разных версий Python. Избегай глобальной установки без необходимости.

## uv

Инструмент для окружений и зависимостей Python.

- **venv --python** — Создать виртуальное окружение (изолированную папку с Python и библиотеками проекта, по умолчанию .venv). Флаг --python выбирает версию интерпретатора для этого окружения, например 3.12; если такой версии нет, uv может скачать её сам. Пример: uv venv --python 3.12
- **run** — Запустить команду или программу в окружении проекта. uv при необходимости создаёт окружение и ставит зависимости, так что не нужно вручную активировать окружение. Пример: uv run python app.py
- **add** — Добавить библиотеку в зависимости проекта: uv записывает её в файл pyproject.toml, устанавливает в окружение и обновляет файл блокировки версий (uv.lock). Пример: uv add requests
- **sync** — Привести окружение в точное соответствие с зависимостями проекта: недостающее установить, лишнее убрать. Выполняют после скачивания проекта или после изменения файла зависимостей. Пример: uv sync
- **tree** — Показать дерево зависимостей проекта: какие пакеты установлены и какие другие пакеты каждый из них за собой тянет. Помогает понять, откуда в окружении взялась та или иная библиотека. Пример: uv tree

**ПРИМЕРЫ**

> uv venv --python 3.12
>
> uv run python --version
>
> uv add requests
>
> uv sync
>
> uv tree

**ПРИМЕР С ВЫВОДОМ**

> **\$ uv venv --python 3.12**
>
> Creating virtual environment at: .venv
>
> **\$ uv add requests**
>
> Resolved 5 packages in 120ms
>
> **\$ uv tree**
>
> project v0.1.0
>
> └── requests v2.32.3
>
> **→** venv создаёт окружение; run запускает команду в нём; add добавляет зависимость; sync приводит окружение к lock-файлу; tree показывает дерево пакетов.
>
> **Нюанс** Обратные кавычки в исходном списке — оформление, не часть команды. uv sync приводит окружение к описанию проекта/lock-файлу.

## apt

Управляет пакетами Debian/Ubuntu.

- **list --installed** — Показать список пакетов, которые установлены в системе. Результат длинный — его удобно фильтровать через grep, например: apt list --installed \| grep python3. Пример: apt list --installed \| grep git
- **list --upgradable** — Показать пакеты, для которых доступна более свежая версия. Список опирается на последнюю загруженную информацию о пакетах, поэтому сначала обычно выполняют sudo apt update. Сама команда ничего не обновляет — только показывает. Пример: apt list --upgradable

**ПРИМЕРЫ**

> apt list --installed
>
> apt list --upgradable

**ПРИМЕР С ВЫВОДОМ**

> **\$ apt list --installed 2\>/dev/null \| head -n 3**
>
> adduser/stable,now 3.134 all \[installed\]
>
> apt/stable,now 2.6.1 amd64 \[installed\]
>
> base-files/stable,now 12.4 amd64 \[installed\]
>
> **\$ apt list --upgradable 2\>/dev/null**
>
> *(список пакетов, для которых доступно обновление; может быть пустым)*
>
> **→** --installed показывает установленные пакеты; --upgradable — доступные обновления.
>
> **Нюанс** Для установки и обновления нужны другие подкоманды; системные изменения обычно требуют sudo.

## systemctl

Показывает и управляет объектами systemd, в том числе службами.

- **--type** — Ограничить вывод объектами определённого типа: service (службы), socket, timer, mount и другие. Без фильтра список состоит из объектов всех типов и очень длинный. Пишется как --type=service или --type service. Пример: systemctl list-units --type=service
- **--no-pager** — Не использовать постраничный просмотр (less): весь вывод печатается сразу в терминал. Нужен в скриптах и когда вывод надо передать в другую команду или сохранить в файл, иначе systemctl может «зависнуть» в ожидании нажатия q. Пример: systemctl status ssh --no-pager

**ПРИМЕРЫ**

> systemctl --type=service --no-pager

**ПРИМЕР С ВЫВОДОМ**

> **\$ systemctl --type=service --no-pager**
>
> UNIT LOAD ACTIVE SUB DESCRIPTION
>
> cron.service loaded active running Regular background program processing daemon
>
> ssh.service loaded active running OpenBSD Secure Shell server
>
> **→** Выведен список служб systemd без открытия постраничного просмотрщика.
>
> **Нюанс** Просмотр и изменение состояния службы — разные действия; для управления часто нужен sudo.

## journalctl

Читает системный журнал systemd.

- **-u** — Unit — показывать записи только одной службы (например, ssh или nginx), а не всей системы. Имя можно писать с окончанием .service или без него. Самый частый способ посмотреть, почему служба не запускается. Пример: journalctl -u ssh
- **-n N** — Показать только последние N записей журнала (по умолчанию 10). Вместо N подставь число. Хорошо сочетается с -u: journalctl -u ssh -n 50. Пример: journalctl -u ssh -n 50
- **--no-pager** — Не открывать постраничный просмотр: весь вывод печатается сразу в терминал. Подходит для скриптов и для передачи вывода в grep или файл. Пример: journalctl -u ssh -n 20 --no-pager

**ПРИМЕРЫ**

> journalctl -u ssh -n 50 --no-pager

**ПРИМЕР С ВЫВОДОМ**

> **\$ journalctl -u ssh -n 3 --no-pager**
>
> Nov 10 10:01:02 host sshd\[812\]: Server listening on 0.0.0.0 port 22.
>
> Nov 10 10:02:14 host sshd\[900\]: Accepted publickey for anna.
>
> Nov 10 10:02:14 host sshd\[900\]: pam_unix(sshd:session): session opened
>
> **→** -u отбирает журнал службы ssh; -n 3 оставляет последние три записи.
>
> **Нюанс** Доступ к системным журналам может быть ограничен; при необходимости используй sudo.

> **Нюанс** Переменная, заданная перед командой в env, действует только для этого запуска. Чтобы изменить окружение самой оболочки, используй export.

## command

- **-v** — Verbose — показать, во что превратится имя команды: путь к программе (/usr/bin/python3), псевдоним (alias) или встроенная команда. Если такой команды нет, ничего не печатает и возвращает ненулевой код. Хорошо подходит для проверки в скриптах: нашёлся ли инструмент. Пример: command -v git

> **Нюанс** Показывает путь к программе или сообщает, что это встроенная команда.

# 6. Оборудование, ресурсы и процессы

## lscpu

Показывает архитектуру и характеристики процессора.

**Использование:** lscpu

**ПРИМЕРЫ**

> lscpu
>
> lscpu \| grep 'Model name'

**ПРИМЕР С ВЫВОДОМ**

>
> **→** Из всего вывода выбраны две строки: число логических процессоров и название модели.
>
> **Нюанс** CPU(s) — число логических процессоров (потоков), оно не всегда равно числу физических ядер. Для ядер смотри строки «Core(s) per socket» и «Thread(s) per core».

## nproc

Показывает число процессоров, доступных текущему процессу.

**Использование:** nproc

**ПРИМЕРЫ**

> nproc
>
> make -j"\$(nproc)"

**ПРИМЕР С ВЫВОДОМ**

## free

Показывает использование RAM и swap.

- **-h** — Human-readable — размеры печатаются в удобных единицах (Ki, Mi, Gi) вместо длинных чисел в килобайтах. Выводятся строки Mem (оперативная память) и Swap (область подкачки на диске). Колонка available показывает, сколько памяти реально доступно программам. Пример: free -h

**ПРИМЕРЫ**

> free -h

**ПРИМЕР С ВЫВОДОМ**

> **\$ free -h**
>
> total used free shared buff/cache available
>
> Mem: 15Gi 4.1Gi 7.2Gi 320Mi 3.7Gi 10Gi
>
> Swap: 2.0Gi 0B 2.0Gi
>
> **→** -h выводит объёмы в удобных единицах. available — оценка памяти, которую приложения ещё могут использовать.
>
> **Нюанс** Поле available часто полезнее, чем free: оно оценивает память, доступную приложениям без активного swap.

## ps

Показывает снимок процессов.

- **-u** — Показать процессы указанного пользователя. После флага указывают имя: ps -u anna. Без -u ps показывает только процессы текущего терминала. Пример: ps -u anna
- **-p** — Показать только процесс с указанным номером PID (идентификатор процесса). Можно перечислить несколько номеров через запятую. Помогает проверить, жив ли конкретный процесс. Пример: ps -p 1234
- **-o** — Output — выбрать, какие колонки выводить, и в каком порядке. Названия колонок перечисляют через запятую: pid (номер), ppid (родитель), user, %cpu, %mem, etime (время работы), cmd (команда). Позволяет получить компактный точный вывод. Пример: ps -o pid,user,%cpu,%mem,cmd -p 1234

**ПРИМЕРЫ**

> ps -u "\$USER"
>
> ps -p 1234
>
> ps -o pid,ppid,stat,comm -p 1234

**ПРИМЕР С ВЫВОДОМ**

> **\$ ps -u anna -o pid,stat,comm**
>
> PID STAT COMMAND
>
> 1420 S bash
>
> 1532 Sl code
>
> 1880 R+ ps
>
> **→** -u выбирает процессы пользователя; -p выбирает конкретный PID; -o задаёт колонки.
>
> **Нюанс** В отличие от top, ps не обновляет данные постоянно.

## top

Интерактивно показывает процессы и нагрузку.

- **q** — Выйти из top (quit).
- **m** — Переключает отображение сводки по памяти: полоски использования памяти и подкачки показываются в разных видах (в виде графика или только числами). Не меняет сортировку процессов — только вид верхней части.
- **P** — Сортировать процессы по загрузке процессора (заглавная P — CPU). Сверху окажутся процессы, которые сильнее всего нагружают процессор.
- **M** — Сортировать процессы по использованию оперативной памяти (заглавная M — Memory). Сверху будут самые «прожорливые» по памяти процессы.

**ПРИМЕРЫ**

> top

**ПРИМЕР С ВЫВОДОМ**

> **\$ top**
>
> %Cpu(s): 3.0 us, 1.0 sy, 96.0 id
>
> MiB Mem : 16000 total, 7200 free, 4100 used
>
> PID USER PR NI VIRT RES %CPU %MEM COMMAND
>
> 1532 anna 20 0 2.1g 420m 8.0 2.6 code
>
> **→** В top нажми P для сортировки по CPU, M — по памяти; q — выход.
>
> **Нюанс** P и M — заглавные буквы; регистр важен. Набор клавиш зависит от версии.

## htop

Удобный интерактивный просмотр процессов, если установлен.

- **F3** — Поиск процесса по имени или части команды. Введи текст — курсор перейдёт к найденному процессу; F3 снова — к следующему совпадению.
- **F6** — Выбор колонки для сортировки: появится меню (CPU, MEM, PID, TIME и другие). Стрелками выбери колонку и нажми Enter.
- **F10** — Выход из htop. Работает так же, как q.

**ПРИМЕРЫ**

> htop

**ПРИМЕР С ВЫВОДОМ**

> **\$ htop**
>
> *(откроется цветной список процессов и полосы CPU/RAM)*
>
> F3 → поиск процесса; F6 → выбор сортировки; F10 → выход
>
> **→** htop интерактивен; внешний вид и доступные клавиши могут немного различаться.
>
> **Нюанс** Если функциональные клавиши перехватывает терминал, используй экранные подсказки htop.

## kill

Отправляет сигнал процессу по PID.

- **-TERM** — Сигнал SIGTERM (по умолчанию, если сигнал не указан): вежливая просьба завершиться. Программа может сохранить данные, закрыть файлы и корректно остановиться. Сначала всегда пробуй именно его. Пример: kill -TERM 1234
- **-KILL** — Сигнал SIGKILL (то же, что -9): система немедленно уничтожает процесс, а сам процесс не может его перехватить или отказаться. Он не успевает сохранить данные, поэтому применяй, только если -TERM не помог. Пример: kill -KILL 1234
- **-STOP** — Сигнал SIGSTOP: приостановить процесс, не завершая его. Процесс «замирает» и не использует процессор, но остаётся в памяти. Перехватить или проигнорировать этот сигнал нельзя. Пример: kill -STOP 1234
- **-CONT** — Сигнал SIGCONT: продолжить работу процесса, ранее остановленного сигналом -STOP (или нажатием Ctrl+Z). Пример: kill -CONT 1234

**ПРИМЕРЫ**

> kill -TERM 1234
>
> kill -KILL 1234
>
> kill -STOP 1234
>
> kill -CONT 1234

**ПРИМЕР С ВЫВОДОМ**

> **\$ kill -TERM 1532**
>
> *(процессу 1532 отправлен запрос на корректное завершение)*
>
> **\$ kill -STOP 1532**
>
> *(процесс приостановлен)*
>
> **\$ kill -CONT 1532**
>
> *(процесс продолжил работу)*
>
> **\$ kill -KILL 1532**
>
> *(процесс принудительно завершён)*
>
> **→** Сначала используй TERM. KILL не даёт процессу сохранить данные или выполнить завершение.
>
> **Нюанс** Начинай с TERM. KILL процесс не может обработать. Для чужих процессов обычно нужны права администратора.

## jobs

Показывает фоновые и остановленные задания текущей оболочки.

**Использование:** jobs

**ПРИМЕРЫ**

> sleep 100 &
>
> jobs

**ПРИМЕР С ВЫВОДОМ**

> **\$ sleep 100 &**
>
> \[1\] 4210
>
> **\$ jobs**
>

>

>
> **Нюанс** jobs видит только задания той оболочки, где выполняется. Остановить задание можно сочетанием Ctrl+Z, вернуть на передний план — fg, продолжить в фоне — bg. Все процессы системы показывает ps.

## lsblk

Показывает диски, разделы и блочные устройства.

- **-o** — Output — выбрать колонки через запятую: NAME (имя), SIZE (размер), TYPE (тип: disk, part), FSTYPE (файловая система), MOUNTPOINT (куда смонтировано), MODEL, UUID. Список доступных колонок покажет lsblk --help. Пример: lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
- **-d** — Disks only — не показывать разделы и вложенные устройства, а только сами диски (устройства верхнего уровня). Получается компактный список физических дисков. Пример: lsblk -d
- **-n** — No headings — не выводить строку заголовка колонок. Удобно, когда результат обрабатывают другой командой или скриптом. Пример: lsblk -n -o NAME
- **-a** — All — показать все устройства, в том числе пустые и те, которые по умолчанию скрыты (например, устройства без носителя). Пример: lsblk -a
- **-f** — Filesystems — показать сведения о файловых системах: тип (ext4, ntfs), метку, UUID, сколько места свободно и где смонтировано. Удобно, чтобы узнать, чем отформатирован раздел. Пример: lsblk -f
- **-J** — JSON — вывести результат в формате JSON (структурированный текст, который легко читать программам и скриптам). Заглавная J обязательна. Пример: lsblk -J
- **-b** — Bytes — показывать размеры точными числами в байтах, а не в удобных единицах. Нужно для вычислений и скриптов. Пример: lsblk -b -o NAME,SIZE

**ПРИМЕРЫ**

> lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS
>
> lsblk -f
>
> lsblk -J
>
> lsblk -d

**ПРИМЕР С ВЫВОДОМ**

> **\$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS**
>
> NAME SIZE FSTYPE MOUNTPOINTS
>
> sda 100G
>
> ├─sda1 99G ext4 /
>
> sdb 500G
>
> └─sdb1 500G ntfs /media/anna/DATA
>
> **→** -o выбирает колонки; -d показывает только устройства; -n убирает заголовок; -a включает пустые устройства; -f файловые системы; -J JSON; -b размеры в байтах.
>
> **Нюанс** Это отдельные флаги. -d скрывает разделы, -f добавляет сведения о файловых системах.

## findmnt

Показывает смонтированные файловые системы.

- **-T** — Target — для указанного пути найти, на какой файловой системе он находится (на каком диске или разделе). Работает для любого пути, а не только для точек монтирования. Отвечает на вопрос «где физически лежит этот каталог». Пример: findmnt -T /home/anna
- **-o** — Output — выбрать колонки через запятую: TARGET (точка монтирования), SOURCE (устройство), FSTYPE (тип файловой системы), OPTIONS (параметры монтирования), AVAIL (свободно). Пример: findmnt -o TARGET,SOURCE,FSTYPE

**ПРИМЕРЫ**

> findmnt -T /home
>
> findmnt -T /var/log -o SOURCE,FSTYPE,TARGET,OPTIONS

**ПРИМЕР С ВЫВОДОМ**

> **\$ findmnt -T /home/anna**
>
> TARGET SOURCE FSTYPE OPTIONS
>
> /home /dev/sda1 ext4 rw,relatime
>
> **→** -T определяет файловую систему, на которой находится указанный путь; -o выбирает столбцы.
>
> **Нюанс** Помогает определить, на каком разделе расположен конкретный каталог.

## df

Показывает свободное и занятое место файловых систем.

- **-h** — Human-readable — размеры в удобных единицах (K, M, G). Без флага числа выводятся в блоках по 1 КБ и читать их сложно. Колонка Use% показывает, насколько заполнена файловая система, а Mounted on — куда она смонтирована. Пример: df -h

**ПРИМЕРЫ**

> df -h
>
> df -h /home

**ПРИМЕР С ВЫВОДОМ**

> **\$ df -h /home**
>
> Filesystem Size Used Avail Use% Mounted on
>
> /dev/sda1 99G 41G 53G 44% /
>
> **→** df показывает занятость всего раздела, а не размер одной папки.
>
> **Нюанс** Показывает место на файловой системе, а не размер отдельной папки.

## du

Оценивает объём места, занятый файлами и каталогами.

- **-s** — Summarize — вывести только итоговый размер указанного каталога, не перечисляя каждый вложенный подкаталог. Без -s du печатает размер каждой папки по пути. Пример: du -s project/
- **-h** — Human-readable — размеры в удобных единицах (K, M, G). Часто сочетают с -s: du -sh project/ покажет общий размер каталога одной строкой. Пример: du -sh project/

**ПРИМЕРЫ**

> du -sh ~/Downloads
>
> du -h project/

**ПРИМЕР С ВЫВОДОМ**

> **\$ du -sh ~/Downloads**
>
> 2.4G /home/anna/Downloads
>
> **→** -s показывает только итог; -h переводит размер в KB/MB/GB.
>
> **Нюанс** df показывает занятость раздела, du — объём выбранного дерева файлов. Результаты могут различаться.

## uname

Показывает сведения о ядре и системе.

- **-a** — All — показать всю информацию одной строкой: имя ядра, имя компьютера, версию ядра, дату сборки, архитектуру, тип ОС. Пример: uname -a
- **-s** — Kernel name — имя ядра операционной системы. На Linux выводит Linux. Пример: uname -s
- **-r** — Kernel release — номер версии ядра, например 6.8.0-45-generic. Нужен, чтобы подобрать драйверы или проверить, что ядро обновилось. Пример: uname -r
- **-m** — Machine — архитектура процессора: x86_64 (обычные 64-битные), aarch64 или arm64 (ARM) и т. д. Важна при скачивании программ для нужной платформы. Пример: uname -m
- **-o** — Operating system — название операционной системы. На Linux выводит GNU/Linux. Пример: uname -o

**ПРИМЕРЫ**

> uname -a
>
> uname -s
>
> uname -r
>
> uname -m
>
> uname -o

**ПРИМЕР С ВЫВОДОМ**

> **\$ uname -a**
>
> Linux laptop 6.8.0-31-generic \#31-Ubuntu SMP x86_64 GNU/Linux
>
> **\$ uname -s; uname -r; uname -m; uname -o**
>
> Linux
>
> 6.8.0-31-generic
>
> x86_64
>
> GNU/Linux
>
> **→** -a всё; -s имя ядра; -r версия ядра; -m архитектура; -o тип ОС.
>
> **Нюанс** -o поддерживается не всеми системами.

## lspci

Показывает устройства PCI/PCIe.

- **-k** — Kernel — для каждого устройства показать, какой драйвер (модуль ядра) им управляет и какие модули могут с ним работать. Помогает понять, загружен ли драйвер видеокарты или сетевой карты. Пример: lspci -k
- **-v** — Verbose — подробный вывод: добавляются возможности устройства, ресурсы, адреса и прочие технические детали. Для ещё большей подробности можно повторить флаг: -vv. Пример: lspci -v
- **-s** — Slot — показать только устройство по его адресу на шине (вид 01:00.0, который можно увидеть в обычном выводе lspci). Так можно посмотреть одно устройство, не листая весь список. Пример: lspci -k -s 01:00.0

**ПРИМЕРЫ**

> lspci -k
>
> lspci -v
>
> lspci -s 01:00.0

**ПРИМЕР С ВЫВОДОМ**

> **\$ lspci -s 00:02.0**
>
> 00:02.0 VGA compatible controller: Intel Corporation UHD Graphics
>
> **\$ lspci -k -s 00:02.0**
>
> Kernel driver in use: i915
>
> Kernel modules: i915
>
> **→** -s выбирает устройство; -k показывает используемый драйвер и доступные модули; -v добавляет подробности.
>
> **Нюанс** Полезно для диагностики видеокарт, сетевых адаптеров и контроллеров.

## nvidia-smi

# 7. Сети и диагностика соединений

## getent

Запрашивает системную базу имён с учётом настроек NSS.

- **hosts** — Спросить у системы адрес по имени узла (и наоборот) так, как это делают обычные программы: с учётом файла /etc/hosts, DNS и других источников, перечисленных в настройках NSS. Для проверки «видит ли система это имя» надёжнее, чем dig, который обращается только к DNS. Пример: getent hosts example.com
- **ahostsv4** — Показать все IPv4-адреса указанного имени, каждый по отдельной записи, с видом соединения (STREAM, DGRAM, RAW). Так видно все адреса, которые получила бы программа при подключении. Версия для IPv6 — ahostsv6, для обоих — ahosts. Пример: getent ahostsv4 example.com

**ПРИМЕРЫ**

> getent hosts example.com
>
> getent ahostsv4 example.com

**ПРИМЕР С ВЫВОДОМ**

> **\$ getent hosts example.com**
>
> 93.184.216.34 example.com
>
> **\$ getent ahostsv4 example.com**
>
> 93.184.216.34 STREAM example.com
>
> 93.184.216.34 DGRAM
>
> 93.184.216.34 RAW
>
> **→** hosts показывает найденный адрес; ahostsv4 запрашивает IPv4-варианты через системную службу имён.
>
> **Нюанс** Результат может отличаться от dig, потому что getent использует системный порядок источников имён.

## ip

Показывает и настраивает интерфейсы, адреса и маршруты.

- **-brief** — Краткий вывод: информация об интерфейсах или адресах печатается компактной таблицей в одну строку на интерфейс, вместо длинного многострочного вывода. Сокращение: -br. Ставится сразу после ip, перед подкомандой. Пример: ip -brief address
- **address** — Подкоманда: работа с IP-адресами сетевых интерфейсов. Без дополнительных слов показывает адреса IPv4 и IPv6 каждого интерфейса. Сокращения: addr, a. (В исходном списке было написано adress — правильно именно address.) Пример: ip address
- **route get** — Спросить у системы, по какому маршруту уйдёт трафик к указанному адресу: через какой шлюз (via), через какой сетевой интерфейс (dev) и с какого своего адреса (src). Помогает понять, почему нет связи с конкретным узлом. Пример: ip route get 1.1.1.1

**ПРИМЕРЫ**

> ip -brief address
>
> ip route get 1.1.1.1

**ПРИМЕР С ВЫВОДОМ**

> **\$ ip -brief address**
>
> lo UNKNOWN 127.0.0.1/8 ::1/128
>
> wlan0 UP 192.168.1.25/24
>
> **\$ ip route get 1.1.1.1**
>
> 1.1.1.1 via 192.168.1.1 dev wlan0 src 192.168.1.25
>
> **→** brief сокращает вывод; address показывает адреса интерфейсов; route get показывает маршрут до указанного IP.
>
> **Нюанс** В исходном списке было adress — правильно address (можно сокращать addr). route get показывает, через какой интерфейс пойдёт трафик.

## ss

Показывает сокеты и порты.

- **-l** — Listening — показывать только слушающие сокеты: порты, на которых программы ждут входящих подключений. Сокеты с уже установленными соединениями не выводятся. Пример: ss -l
- **-t** — TCP — показывать только TCP-соединения (надёжный протокол: веб, SSH, почта). Пример: ss -t
- **-u** — UDP — показывать только UDP-сокеты (протокол без установки соединения: DNS, часть игр и потоковой передачи). Пример: ss -u
- **-n** — Numeric — не переводить числа в имена: порты показываются номерами (22, а не ssh), адреса — цифрами. Вывод быстрее и однозначнее, потому что не нужно спрашивать DNS. Пример: ss -tn
- **-p** — Process — показать, какой процесс держит сокет (имя программы и PID). Для процессов других пользователей нужны права администратора (sudo). Пример: sudo ss -ltnp

**ПРИМЕРЫ**

> ss -ltn
>
> ss -lun
>
> ss -ltnp

**ПРИМЕР С ВЫВОДОМ**

> **\$ ss -ltn**
>
> State Recv-Q Send-Q Local Address:Port Peer Address:Port
>
> LISTEN 0 128 0.0.0.0:22 0.0.0.0:\*
>
> LISTEN 0 listen 0 128 127.0.0.1:5432 0.0.0.0:\*
>
> **→** -l слушающие порты; -t TCP; -u UDP; -n числа вместо имён; -p имя процесса (если хватает прав).
>
> **Нюанс** -p может требовать повышенных прав. -ltnp показывает слушающие TCP-порты с процессами.

## nc (netcat)

Создаёт TCP/UDP-соединение; полезен для проверки порта.

- **-z** — Zero-I/O — режим сканирования: только проверить, открыт ли порт, и сразу закрыть соединение, не отправляя и не читая данные. Результат виден по коду завершения и (с -v) по сообщению. Пример: nc -z example.com 443
- **-v** — Verbose — подробный вывод: сообщает, удалось ли подключиться, к какому адресу и порту. Без -v при успешной проверке с -z команда молчит. Пример: nc -zv example.com 22
- **-w** — Wait — максимальное время ожидания подключения в секундах. Если за это время ответа нет, nc сдаётся и завершается с ошибкой. Без -w команда может ждать очень долго. Пример: nc -z -w 3 example.com 80
- **-u** — UDP — использовать UDP вместо TCP (по умолчанию nc работает по TCP). Проверка UDP менее надёжна: отсутствие ответа не обязательно означает, что порт закрыт. Пример: nc -u -z example.com 53

**ПРИМЕРЫ**

> nc -z -v -w 3 example.com 443
>
> nc -u -z -v -w 2 127.0.0.1 53

**ПРИМЕР С ВЫВОДОМ**

> **\$ nc -z -v -w 3 example.com 443**
>
> Connection to example.com 443 port \[tcp/https\] succeeded!
>
> **→** -z проверяет порт без передачи данных; -v показывает результат; -w 3 ждёт не более трёх секунд; -u переключает на UDP.
>
> **Нюанс** Существуют разные реализации netcat, поэтому опции могут отличаться. Успешная UDP-проверка не всегда доказывает, что сервис отвечает.

## curl

Отправляет HTTP-запросы и сохраняет/показывает ответы.

- **-v** — Verbose — подробный вывод: показывает установку соединения, отправляемые заголовки (строки с \>), полученные заголовки (строки с \<) и подробности TLS. Главный инструмент отладки. Осторожно: в вывод попадают заголовки с токенами и паролями — не публикуй его. Пример: curl -v https://example.com
- **-H** — Header — добавить HTTP-заголовок к запросу. Заголовок берут в кавычки в виде «Имя: значение». Флаг можно повторять несколько раз. Так передают тип данных (Content-Type), токен авторизации (Authorization) и т. д. Пример: curl -H 'Accept: application/json' https://example.com/api
- **--data-raw** — Отправить указанный текст как тело запроса (метод автоматически становится POST). «Raw» значит, что текст передаётся как есть, без особой обработки знака @ в начале (в отличие от -d, где @файл означает чтение из файла). Часто используется для отправки JSON. Пример: curl --data-raw '{"ok":true}' https://example.com/api
- **--connect-timeout** — Максимальное время в секундах, которое curl ждёт установки соединения с сервером. Если сервер не отвечает, curl прекращает попытки с ошибкой. Ограничивает только этап подключения, а не весь запрос. Пример: curl --connect-timeout 5 https://example.com
- **--max-time** — Максимальное время в секундах на весь запрос целиком: подключение, отправка и получение ответа. Когда время вышло, curl прерывает операцию, даже если ответ ещё скачивается. Защищает от зависаний. Пример: curl --max-time 20 https://example.com
- **--noproxy** — Не использовать прокси для перечисленных адресов (через запятую), даже если прокси настроен в переменных окружения. Для всех адресов — звёздочка в кавычках: --noproxy '\*'. Нужен для обращения к локальным и внутренним серверам. Пример: curl --noproxy localhost http://localhost:8000
- **-sS** — Это два флага вместе: -s (silent) скрывает индикатор прогресса и служебные сообщения, а -S (show-error) возвращает вывод сообщений об ошибках, которые -s иначе тоже скрыл бы. Получается «тихо, но об ошибках сообщить» — удобно для скриптов. Пример: curl -sS https://example.com
- **-o** — Output — сохранить тело ответа в указанный файл вместо вывода на экран. Без -o содержимое страницы заливает терминал. Для сохранения под именем с сервера есть -O (заглавная). Пример: curl -o page.html https://example.com
- **-w** — Write-out — после завершения запроса напечатать заданные сведения по шаблону. В шаблоне можно использовать переменные: %{http_code} (код ответа), %{time_total} (общее время), %{size_download} (число скачанных байтов). Шаблон берут в кавычки. Пример: curl -sS -o /dev/null -w '%{http_code}' https://example.com
- **--http1.1** — Принудительно использовать версию протокола HTTP/1.1, а не более новые HTTP/2 или HTTP/3. Нужен для отладки и для серверов, которые некорректно работают с новыми версиями. Пример: curl --http1.1 -I https://example.com

**ПРИМЕРЫ**

> curl -v https://example.com
>
> curl -H "Content-Type: application/json" --data-raw '{"ok":true}' https://example.com/api
>
> curl --connect-timeout 5 --max-time 20 https://example.com
>
> curl -sS -o page.html -w "HTTP %{http_code}\n" https://example.com
>
> curl --http1.1 --noproxy localhost http://localhost:8000

**ПРИМЕР С ВЫВОДОМ**

> **\$ curl -sS -o /tmp/page.html -w 'HTTP %{http_code}; bytes %{size_download}\n' --connect-timeout 3 --max-time 10 https://example.com**
>
> HTTP 200; bytes 1256
>
> **→** -sS скрывает прогресс, но оставляет ошибки; -o сохраняет тело; -w печатает выбранные сведения; лимиты задают время подключения и всего запроса. -H добавляет заголовок, --data-raw отправляет тело, -v включает подробности, --noproxy обходит прокси, --http1.1 выбирает HTTP/1.1.
>
> **Нюанс** -o сохраняет тело ответа, -w печатает дополнительную информацию. Не включай -v в общий лог, если передаёшь секретные заголовки или токены.

## dig

Делает DNS-запрос.

- **@сервер** — Указать, у какого DNS-сервера спрашивать, вместо настроенного в системе. Адрес пишется сразу после @ без пробела, например @1.1.1.1 (Cloudflare) или @8.8.8.8 (Google). Позволяет сравнить ответы разных серверов. Пример: dig @1.1.1.1 example.com
- **A** — Тип записи DNS, которую запрашиваем: A — IPv4-адрес сайта. Другие часто используемые типы: AAAA (IPv6), MX (почтовые серверы), TXT (текстовые данные), NS (серверы имён), CNAME (псевдоним). Пример: dig example.com A
- **+short** — Выдать только короткий ответ: сами значения (например, IP-адрес) без заголовков, сведений о запросе и прочего пояснительного текста. Удобно для скриптов и быстрой проверки. Пример: dig example.com A +short

**ПРИМЕРЫ**

> dig example.com A
>
> dig @1.1.1.1 example.com A +short

**ПРИМЕР С ВЫВОДОМ**

> **\$ dig @1.1.1.1 example.com A +short**
>
> 93.184.216.34
>
> **→** @1.1.1.1 задаёт DNS-сервер, A — запрос IPv4-адреса, +short оставляет короткий ответ.
>
> **Нюанс** Если сервер не указан, используется настроенный DNS.

## ping

Отправляет ICMP-запросы и измеряет время ответа.

- **-c N** — Count — отправить ровно N запросов и завершиться, вместо бесконечной отправки до нажатия Ctrl+C. В конце выводится итог: сколько пакетов потеряно и среднее время ответа. Без -c на Linux ping работает бесконечно. Пример: ping -c 4 example.com

**ПРИМЕРЫ**

> ping -c 4 example.com

**ПРИМЕР С ВЫВОДОМ**

> **\$ ping -c 4 example.com**
>
> PING example.com (93.184.216.34) 56(84) bytes of data.
>
> 64 bytes from 93.184.216.34: icmp_seq=1 ttl=56 time=18.4 ms
>
> 64 bytes from 93.184.216.34: icmp_seq=2 ttl=56 time=17.9 ms
>
> --- example.com ping statistics ---
>
> 4 packets transmitted, 4 received, 0% packet loss
>
> **→** -c 4 отправил четыре запроса и завершил работу.
>
> **Нюанс** Отсутствие ответа не обязательно означает, что сервер недоступен: ICMP может блокироваться.

# 8. SSH, передача файлов и удалённая работа

## ssh

Защищённо подключается к удалённой машине.

- **-p** — Port — подключиться к указанному номеру порта вместо стандартного 22. Нужен, если администратор сервера перенёс SSH на другой порт. (Обрати внимание: у scp то же самое пишется заглавной -P.) Пример: ssh -p 2222 anna@example.com
- **-i** — Identity — указать файл закрытого ключа для входа. Без этого ssh перебирает стандартные ключи из ~/.ssh. Нужен, когда ключей несколько или файл назван нестандартно. Права на файл ключа должны быть строгими (600), иначе ssh откажется им пользоваться. Пример: ssh -i ~/.ssh/id_ed25519 anna@example.com
- **-F** — Config File — использовать другой файл конфигурации вместо стандартного ~/.ssh/config. Полезно для отдельных проектов или проверки настроек. Можно передать /dev/null, чтобы не использовать никакую пользовательскую конфигурацию. Пример: ssh -F ./myconfig server1
- **-v** — Verbose — подробный отладочный вывод. Показывает, как проходит соединение: какие ключи пробуются, как идёт обмен. Если не получается войти, это первое, что нужно запустить. Чем больше v (-vv, -vvv), тем подробнее вывод. Пример: ssh -v anna@example.com
- **-T** — Не выделять псевдотерминал (отключить интерактивность). Нужен, когда надо просто выполнить команду или проверить доступ, как, например, при проверке подключения к GitHub, или когда вывод пойдёт в скрипт. Пример: ssh -T git@github.com
- **-G** — Показать итоговую конфигурацию для указанного узла (с учётом ~/.ssh/config и других правил), и выйти, не подключаясь. Помогает понять, какие параметры реально применятся: порт, пользователь, ключ. Пример: ssh -G example.com
- **-N** — Не выполнять удалённую команду и не открывать оболочку: подключение нужно только для проброса портов (туннелей). Обычно сочетают с -L или -R. Соединение остаётся открытым, пока не прервёшь его Ctrl+C. Пример: ssh -N -L 8080:localhost:80 anna@example.com
- **-L** — Local forward — локальный туннель: порт на твоём компьютере перенаправляется через SSH на адрес и порт, доступные удалённой стороне. Формат: -L локальный_порт:адрес:порт. Так можно открыть у себя сервис, который доступен только с сервера. Пример: ssh -L 8080:localhost:80 anna@example.com
- **-R** — Remote forward — обратный туннель: порт на удалённом сервере перенаправляется на адрес и порт, доступные с твоего компьютера. Формат: -R удалённый_порт:адрес:порт. Позволяет сделать локальный сервис доступным с сервера. Пример: ssh -R 9000:localhost:3000 anna@example.com
- **-o** — Option — задать любую настройку так, как она пишется в файле конфигурации, в формате «Имя=значение». Можно повторять. Например, StrictHostKeyChecking, ConnectTimeout, ServerAliveInterval. Удобна для разовых изменений без правки файла. Пример: ssh -o ConnectTimeout=5 anna@example.com

**ПРИМЕРЫ**

> ssh alice@example.com
>
> ssh -p 2222 alice@example.com
>
> ssh -i ~/.ssh/id_ed25519 alice@example.com
>
> ssh -F ~/.ssh/config server
>
> ssh -N -L 8080:127.0.0.1:80 alice@server

**ПРИМЕР С ВЫВОДОМ**

> **\$ ssh -p 2222 -i ~/.ssh/id_ed25519 anna@example.com**
>
> *(после успешной проверки ключа откроется удалённая оболочка)*
>
> **\$ ssh -N -L 8080:127.0.0.1:80 anna@example.com**
>
> *(терминал останется занят туннелем; открой http://127.0.0.1:8080 локально)*
>
> **→** -p порт; -i ключ; -F файл настроек; -v отладка; -T без псевдотерминала; -G показать итоговые настройки; -N не запускать удалённую команду; -L локальный туннель; -R обратный туннель; -o задаёт параметр подключения.
>
> **Нюанс** -L перенаправляет локальный порт к адресу/порту с удалённой стороны. -R открывает порт на удалённой стороне. -o ConnectTimeout=5 задаёт настройку подключения.

## ssh-keygen

Создаёт SSH-ключи и работает с отпечатками/записями серверов.

- **-t** — Type — тип создаваемого ключа. Рекомендуют ed25519 (современный, короткий и быстрый); также распространён rsa (обычно с -b 4096, где -b задаёт длину ключа). Пример: ssh-keygen -t ed25519
- **-f** — File — путь и имя файла, куда сохранить закрытый ключ. Открытый ключ запишется рядом, с добавлением .pub. Без -f программа спросит имя интерактивно, предложив ~/.ssh/id_ed25519 (или id_rsa). Пример: ssh-keygen -t ed25519 -f ~/.ssh/work_key
- **-C** — Comment — комментарий, который запишется в открытый ключ. Обычно туда ставят почту или имя компьютера, чтобы потом узнать, чей это ключ. На работу ключа не влияет. Пример: ssh-keygen -t ed25519 -C 'anna@laptop'
- **-N** — New passphrase — задать парольную фразу, защищающую закрытый ключ, прямо в команде. Пустая строка '' означает «без пароля». Внимание: фраза остаётся в истории команд и видна другим в списке процессов; обычно безопаснее ввести её по запросу, не указывая -N. Пример: ssh-keygen -t ed25519 -N '' -f ./test_key
- **-l** — List — показать отпечаток ключа (короткая контрольная сумма), его длину и тип. Для сверки двух ключей достаточно сравнить отпечатки. Работает с файлом ключа: ssh-keygen -l -f файл. Пример: ssh-keygen -l -f ~/.ssh/id_ed25519.pub
- **-F** — Find — найти запись о хосте в файле known_hosts (список серверов, к которым уже подключались, с их ключами). Показывает, известен ли тебе этот сервер. Пример: ssh-keygen -F example.com
- **-R** — Remove — удалить из known_hosts все ключи указанного хоста. Нужен, когда сервер переустановили и ключ изменился: ssh в таком случае отказывается подключаться с предупреждением REMOTE HOST IDENTIFICATION HAS CHANGED. После удаления при следующем входе ключ будет принят заново — убедись, что смена ключа ожидаема. Пример: ssh-keygen -R example.com

**ПРИМЕРЫ**

> ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -C "laptop" -N ""
>
> ssh-keygen -l -F example.com
>
> ssh-keygen -R example.com

**ПРИМЕР С ВЫВОДОМ**

> **\$ ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -C 'laptop' -N ''**
>
> Your identification has been saved in /home/anna/.ssh/id_ed25519
>
> Your public key has been saved in /home/anna/.ssh/id_ed25519.pub
>
> **\$ ssh-keygen -l -f ~/.ssh/id_ed25519.pub**
>
> 256 SHA256:AbCd... laptop (ED25519)
>
> **→** Созданы закрытый и открытый ключи; -l показывает отпечаток. -F ищет хост в known_hosts, -R удаляет его запись.
>
> **Нюанс** Закрытый ключ (без .pub) никому не передавай. Публичный ключ .pub можно размещать на сервере.

## ssh-agent

Запускает или завершает агент, который хранит расшифрованные ключи в памяти.

- **-s** — Выводить команды для настройки переменных окружения в стиле оболочки sh/bash (для csh есть -c). Обычно запускают как eval "$(ssh-agent -s)": тогда переменные SSH_AUTH_SOCK и SSH_AGENT_PID сразу устанавливаются в текущей оболочке, и другие программы находят агента. Пример: eval "$(ssh-agent -s)"
- **-k** — Kill — завершить работающий агент, чей номер процесса указан в переменной SSH_AGENT_PID. Ключи, загруженные в агент, из памяти пропадают. Пример: ssh-agent -k

**ПРИМЕРЫ**

> eval "\$(ssh-agent -s)"
>
> ssh-agent -k

**ПРИМЕР С ВЫВОДОМ**

> **\$ eval "\$(ssh-agent -s)"**
>
> Agent pid 2450
>
> **\$ ssh-agent -k**
>
> unset SSH_AUTH_SOCK;
>
> unset SSH_AGENT_PID;
>
> echo Agent pid 2450 killed;
>
> **→** -s печатает команды для настройки переменных оболочки; -k завершает агент. Это разные действия.
>
> **Нюанс** Это разные режимы, обычно их выполняют отдельно. eval применяет переменные, напечатанные агентом, в текущей оболочке.

## ssh-add

Добавляет ключ в агент или показывает загруженные ключи.

- **-l** — List — показать список ключей, которые сейчас загружены в агент, в виде отпечатков (контрольных сумм). Если ключей нет, сообщит «The agent has no identities». Помогает проверить, загрузился ли ключ. Пример: ssh-add -l

**ПРИМЕРЫ**

> ssh-add ~/.ssh/id_ed25519
>
> ssh-add -l

**ПРИМЕР С ВЫВОДОМ**

> **\$ ssh-add ~/.ssh/id_ed25519**
>
> Identity added: /home/anna/.ssh/id_ed25519 (laptop)
>
> **\$ ssh-add -l**
>
> 256 SHA256:AbCd... laptop (ED25519)
>
> **→** Ключ добавлен в запущенный агент; -l показывает отпечатки загруженных ключей.
>
> **Нюанс** Если агент не запущен или переменные окружения не настроены, команда не сможет с ним связаться.

## ssh-keyscan

Получает публичные host keys SSH-сервера.

- **-t** — Type — тип запрашиваемого ключа сервера: ed25519, rsa, ecdsa (можно перечислить через запятую). Без флага запрашиваются стандартные типы. Нужен, чтобы получить ключ именно того типа, что вам нужен. Пример: ssh-keyscan -t ed25519 example.com
- **-p** — Port — порт, к которому подключаться, если SSH-сервер работает не на 22. Пример: ssh-keyscan -p 2222 example.com

**ПРИМЕРЫ**

> ssh-keyscan -t ed25519 -p 2222 example.com

**ПРИМЕР С ВЫВОДОМ**

> **\$ ssh-keyscan -t ed25519 -p 2222 example.com**
>
> \[example.com\]:2222 ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA...
>
> **→** Получен открытый ключ сервера. Сам по себе вывод не доказывает подлинность: отпечаток нужно сверить с доверенным источником.
>
> **Нюанс** Получить ключ не значит проверить подлинность сервера. Сверь отпечаток с доверенным источником.

## scp

Копирует файлы между локальной и удалённой машиной через SSH.

- **-r** — Recursive — копировать каталоги целиком, вместе со всем содержимым и вложенными папками. Без -r scp откажется копировать каталог. Пример: scp -r project/ anna@example.com:/srv/
- **-p** — Preserve — сохранить исходные времена изменения и доступа и права файлов у копии. Без этого флага копия получает текущее время и права по умолчанию. (Строчная p — не порт, а сохранение атрибутов.) Пример: scp -p report.txt anna@example.com:/tmp/
- **-P** — Port — порт SSH на удалённой машине, если он не стандартный 22. Пишется заглавной буквой, в отличие от ssh -p (у scp строчная -p уже занята флагом сохранения атрибутов). Пример: scp -P 2222 file.txt anna@example.com:/tmp/

**ПРИМЕРЫ**

> scp report.txt alice@server:/home/alice/
>
> scp -r project/ alice@server:/home/alice/
>
> scp -P 2222 -p report.txt alice@server:/home/alice/

**ПРИМЕР С ВЫВОДОМ**

> **\$ scp -P 2222 -p report.txt anna@example.com:/home/anna/**
>
> report.txt 100% 120 20.0KB/s 00:00
>
> **\$ scp -r project/ anna@example.com:/home/anna/**
>
> *(каталог project и его файлы скопированы на сервер)*
>
> **→** -P задаёт порт; -p сохраняет времена и права; -r копирует каталоги рекурсивно. Стандартного флага -m у scp нет.
>
> **Нюанс** В записи «-rm P, p» флаг -m не является стандартной опцией scp. Вероятно, опечатка. Заглавная -P задаёт порт, строчная -p сохраняет атрибуты.

## rsync

Синхронизирует каталоги, передавая изменения.

- **-a** — Archive — «архивный» режим: набор флагов, который копирует рекурсивно и сохраняет почти всё важное: права, владельцев, времена изменения, символические ссылки. Именно с него начинают почти любое копирование и резервирование. Пример: rsync -a project/ backup/project/
- **-v** — Verbose — подробный вывод: печатает список копируемых файлов. С -vv ещё подробнее. Без него rsync работает молча. Пример: rsync -av project/ backup/project/
- **-n** — Dry run (--dry-run) — «пробный запуск»: показывает, что было бы сделано, но ничего реально не копирует и не удаляет. Обязательно используй вместе с --delete перед настоящим запуском. Пример: rsync -avn --delete project/ backup/project/
- **-i** — Itemize changes — для каждого файла выводит короткий код изменения, например \>f+++++++++ (новый файл) или \>f.st...... (изменились размер и время). Позволяет увидеть, что именно и почему будет передано. Пример: rsync -avni project/ backup/project/
- **--delete** — Удалять в каталоге назначения файлы, которых нет в источнике, чтобы получить точную копию. Опасно: если перепутать источник и назначение или указать неверный путь, можно потерять данные. Сначала проверь запуском с -n. Пример: rsync -av --delete project/ backup/project/
- **--exclude** — Исключить из копирования файлы и каталоги, подходящие под шаблон: --exclude='\*.tmp', --exclude='.git/'. Флаг можно повторять. Шаблон лучше брать в кавычки, чтобы его не раскрыла оболочка. Пример: rsync -av --exclude='.git/' project/ backup/project/
- **-e** — Explicit remote shell — указать программу и её параметры, через которую rsync соединяется с удалённой машиной. Обычно это ssh, и здесь же задают порт или ключ: -e 'ssh -p 2222 -i ~/.ssh/key'. Нужен для нестандартных портов или особых ключей. Пример: rsync -av -e 'ssh -p 2222' project/ anna@example.com:/srv/project/

**ПРИМЕРЫ**

> rsync -av project/ backup/project/
>
> rsync -avn --delete project/ backup/project/
>
> rsync -av --exclude=".git/" -e "ssh -p 2222" project/ alice@server:/srv/project/

**ПРИМЕР С ВЫВОДОМ**

> **\$ rsync -avni --exclude='\*.tmp' -e 'ssh -p 2222' project/ anna@example.com:/backup/project/**
>
> sending incremental file list
>
> \>f+++++++++ index.html
>
> cd+++++++++ images/
>

## tmux

Держит терминальные сессии и программы работающими после отключения окна/SSH.

- **new-session -s имя** — Создать новую сессию с указанным именем (-s — session name) и сразу подключиться к ней. Сессия — это «рабочее пространство» с окнами и программами, которое продолжает жить, даже если закрыть окно терминала или оборвалось SSH-соединение. Сокращённо: tmux new -s имя. Пример: tmux new-session -s work
- **new-session -d** — Detached — создать сессию в фоне, не подключаясь к ней. Удобно для запуска долгих задач (в сочетании с -s имя, чтобы потом найти сессию): программа работает, а твой терминал остаётся свободным. Пример: tmux new-session -d -s job
- **attach -t** — Подключиться (-t — target) к уже существующей сессии по имени. Если сессий несколько и имя не указано, tmux подключится к последней использованной. Сокращённо: tmux a -t имя. Пример: tmux attach -t job
- **list-sessions** — Показать список всех запущенных сессий: имя, число окон и время создания. Сокращённо: tmux ls. Пригодится, чтобы узнать имя сессии перед подключением. Пример: tmux list-sessions
- **kill-session -t** — Завершить указанную сессию (-t — target) вместе со всеми программами в ней. Выполняй осторожно: несохранённая работа в окнах пропадёт. Пример: tmux kill-session -t job
- **Ctrl+B, затем d** — Отсоединиться (detach) от сессии, не завершая её. Сначала нажми Ctrl+B (префикс — «команда для tmux»), отпусти обе клавиши и после этого нажми d. Сессия и все её программы продолжают работать в фоне; вернуться можно через tmux attach.

**ПРИМЕРЫ**

> tmux new-session -s work
>
> tmux new-session -d -s job
>
> tmux list-sessions
>
> tmux attach -t job
>
> tmux kill-session -t job

**ПРИМЕР С ВЫВОДОМ**

> **\$ tmux new-session -d -s job**
>
> **\$ tmux list-sessions**
>
> job: 1 windows (created Tue Nov 10 10:00:00 2026)
>
> **\$ tmux attach -t job**
>
> *(подключение к сессии job)*
>
> Ctrl+B, затем d → отсоединиться, оставив сессию работать
>
> **\$ tmux kill-session -t job**
>
> *(сессия job завершена)*
>
> **→** new-session -s создаёт и открывает сессию; -d создаёт в фоне; attach подключает; list-sessions показывает; kill-session завершает.
>
> **Нюанс** Чтобы отсоединиться, нажми Ctrl+B, отпусти, затем d. Сессия и программы продолжают работать.

# Короткая памятка о важных тонкостях

- rm -rf: удаляет без вопросов и вместе с содержимым. Проверяй pwd и полный путь.

- chmod 640: владелец rw-, группа r--, остальные без прав.

- chgrp: обычный пользователь должен быть владельцем файла и состоять в целевой группе; иначе нужны права администратора.

- grep -v: выводит строки, которые НЕ совпали с шаблоном.

- find -print0 \| xargs -0: безопасная передача имён с пробелами и необычными символами.

- git add подготавливает изменения, git commit записывает их в историю.

- git reset --hard уничтожает незакоммиченные изменения в отслеживаемых файлах.

- git clean -n только показывает, что будет удалено; начинай именно с него.

- ssh-keyscan не проверяет подлинность полученного ключа сервера — отпечаток нужно сверить.

- scp -P задаёт порт, scp -p сохраняет атрибуты.

- rsync --delete удаляет лишнее в папке назначения; перед запуском используй -n.

- В nano Ctrl+O — это буква O, не цифра 0.

# Мини-словарь

- **Терминал** — Окно для ввода команд и просмотра результата.
- **Оболочка (shell)** — Программа, которая читает команды; здесь чаще всего Bash.
- **Путь** — Адрес файла или каталога.
- **Процесс** — Запущенная программа; PID — её числовой номер.
- **Права доступа** — Разрешения читать, изменять и выполнять для владельца, группы и остальных.
- **Репозиторий Git** — Папка проекта и его история изменений.
- **Коммит** — Сохранённый снимок подготовленных изменений.
- **Ветка** — Отдельная линия истории, в которой можно вести работу независимо.
- **Порт** — Номер сетевой точки, на которой программа принимает соединения.
- **Конвейер ( \| )** — Передаёт вывод одной команды на вход следующей.
